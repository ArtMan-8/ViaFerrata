# ADR-0003: Поддержка Linux, macOS и Windows с CI-матрицей

## Context and Problem Statement

`vf` запускается на машинах разработчиков и в хуках агентов/git, поэтому переносимость — часть продуктового контракта. Локальная среда разработки — WSL2; нативные macOS и Windows нельзя считать проверенными локально. Один JS-артефакт уменьшает платформенные различия, но не исключает их.

## Decision Drivers

- Linux, macOS и Windows поддерживаются с первого дня.
- Минимальная и актуальная LTS-версии Node проверяются на каждой ОС.
- Проверки ловят различия путей, прав, переводов строк и запуска хуков.
- Граница доказательства поддержки формулируется явно.

## Considered Options

- Только Linux до релиза.
- Три ОС × минимальная и актуальная LTS Node в GitHub Actions.
- Три ОС × только актуальная LTS Node.
- Linux в контейнере плюс отдельные проверки macOS/Windows.
- Собственные CI-раннеры.

## Decision Outcome

Chosen option: **три ОС × минимальная и актуальная LTS Node в GitHub Actions**.

- **Поддерживаемые ОС:** Linux, macOS и Windows в пределах платформ, поддерживаемых выбранной версией Node. Минимумы Node (например, glibc и версии ОС) — нижняя граница совместимости рантайма, а не самостоятельная гарантия ViaFerrata для каждого дистрибутива, версии ОС или архитектуры. Продуктовые ограничения уточняются по мере проверки; README не меняется в рамках этого ADR.
- **CI:** GitHub Actions, поскольку репозиторий и защита `trunk` находятся на GitHub. Матрица включает три ОС и две версии Node: продуктовый минимум `24.22.2` и актуальную LTS-версию Node. Минимум — нижняя граница `engines.node`, а не указание использовать только Node 24. Точные runner labels, версии Node и образы раннеров — изменяемая конфигурация CI, а не архитектурный контракт.
- **Обязательные проверки:** тесты на каждой ячейке матрицы; typecheck отдельно; запуск/упаковка на чистой среде без runtime-зависимостей; тесты путей с пробелами и Unicode. Конкретные job names и runner images находятся в CI-конфигурации.
- **Портируемость:** общие правила кодирования и соответствующие regression-тесты проверяются тестами и CI. Они не являются самостоятельными требованиями к поддерживаемым ОС сверх заявленного контракта.
- **Нативный Windows:** тестируется нативно, не через WSL. Ограничения sandbox/барьера ОС документируются как ограничения конкретного хоста/режима, а не как отказ от поддержки Windows.

### Consequences

- Хорошо: заявленные ОС и обе версии Node проверяются до слияния; CI ловит дефекты, не воспроизводимые в WSL2.
- Плохо: шесть матричных прогонов; macOS CI дороже; runner images и версии Node нужно обновлять.
- Ограничение доказательства: успешный CI означает проверку конкретных runner images, архитектур и версий Node, а не всех конфигураций ОС/архитектур. Документированные минимумы ОС Node не расширяют это доказательство.

### Confirmation

- Required checks проходят на PR по всем ячейкам матрицы; падение блокирует слияние.
- Внесённые дефекты переносимости воспроизводятся regression-тестами.
- `doctor` показывает runtime, ОС и применимые ограничения среды.

## Pros and Cons of the Options

### Только Linux до релиза

- Хорошо: дешевле и быстрее.
- Плохо: не проверяет две заявленные платформы; WSL2 не заменяет нативный Windows.

### Три ОС × минимальная и актуальная LTS Node

- Хорошо: покрывает заявленный минимум и актуальную LTS на каждой ОС.
- Плохо: шесть прогонов и дополнительная стоимость macOS.

### Три ОС × только актуальная LTS Node

- Хорошо: вдвое меньше прогонов.
- Плохо: минимальная версия Node не проверяется регулярно.

### Linux в контейнере плюс macOS/Windows

- Хорошо: потенциально дешевле.
- Плохо: контейнер не заменяет нативную проверку особенностей ОС.

### Собственные раннеры

- Хорошо: полный контроль среды.
- Плохо: обслуживание и безопасность несоразмерны масштабу проекта.
