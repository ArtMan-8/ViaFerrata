# Синхронизация и архивирование

Читай перед применением дельты к SRS, архивированием, отменой задачи, выводом постоянного документа из использования или продолжением прерванной процедуры. Применяй вместе с [общими правилами](workflow.md); форму дельты определяет [руководство шаблонов](../templates/README.md#дельта-требований).

## Применение дельты

При успешном `vf complete change-NNNNNN` рабочий Plan получает `execution: completed`. Если Spec содержит принятую дельту к SRS, агент применяет её и архивирует комплект в рамках одной процедуры. Если работа продолжается после прерывания, начни со сверки состояния документов.

1. Сверь согласованную дельту с фактическими постоянными документами. Текст `before` должен соответствовать исходному обязательству; расхождение требует разрешения конфликта. При продолжении сравни `before` и `after`, установи уже выполненные действия и не применяй их повторно. Восстанавливай ход синхронизации по фактическому состоянию документов; процедура не атомарна для нескольких файлов.
2. Примени оставшуюся дельту: перенеси результирующие требования в SRS, обнови контекст и Verification. При remove убери отменённое R, не превращая отмену обязанности в запрет. Сохрани ID изменённого требования; для нового выбери свободный номер с учётом отменённых R в дельтах и Git.
3. Проверь постоянные документы и соответствие принятой дельте по [инструкции проверки артефактов](artifact-review.md). Доработка реализации или её проверок возвращает execution в работу; изменение целевого обязательства требует согласования.
4. Немедленно перенеси полный комплект в archive/changes/change-NNNNNN внутри documents_root. Содержание завершённого change сохраняется; записи об архивировании в Journal не добавляются. Между артефактами используй логические ID. Проверь входящие ссылки и сохранность материалов; при наличии относительных файловых ссылок исправь пути, нарушенные перемещением. Занятый путь назначения не перезаписывай.

## Архивирование, отмена и вывод документов

У change без дельты к SRS синхронизация и архивирование необязательны. При отмене частично выполненной задачи сначала определи судьбу результата. По принятому решению сохрани результат частично или выполни откат. Непринятую дельту не применяй. Если реализация не начиналась, ненужный черновой комплект можно удалить без создания Journal или дополнительных записей. До удаления проверь входящие ссылки и разрешение на удаление по правилам проекта. Команда `vf new change` назначает следующий номер после максимального рабочего или архивного, включая номер занятого каталога. При удалении комплекта с наибольшим номером этот номер может освободиться для следующего change.

Архивировать change можно только при execution completed/cancelled. SRS/ADR переносятся в archive/specs и archive/adr при status cancelled/superseded. При замене целой SRS новая указывает supersedes того же типа. При отмене последнего R последняя содержательная SRS становится cancelled и переносится целиком; пустая активная SRS не остаётся. Research переносится в archive/research при completed/cancelled/superseded и установленной потере дальнейшей применимости. Возраст и завершённость сами по себе не служат основанием. Основание выбытия самостоятельного документа задай в нём или сопровождающем change до завершения. Редакции хранятся в Git; архив предназначен для выбывших документов.

## Восстановление и ссылки

Неархивный completed-change с дельтой означает незавершённую процедуру, но не доказывает, что SRS ещё не изменена. Отдельное состояние синхронизации не вводится. После прерванного переноса сверь оба расположения и восстанови комплект; наличие архивного каталога само по себе не означает завершения.

Текущая содержательная зависимость от архива вызывает предупреждение; origin/supersedes допустимы как происхождение. Перенос не требует заранее исправлять все входящие зависимости, их источники меняются по потребности. Исторические ссылки не переписывай автоматически. Сохранённая дельта remove позволяет найти отменённую идентичность и текст `before`, но не доказывает редакцию во время прежней проверки; конкретная редакция восстанавливается через Git. Если опоры нет, сохрани явное ограничение, не подставляй произвольный текст.
