# Работа в ViaFerrata

## Контекст

- Прочитай [README](README.md), [общие правила](instructions/workflow.md) и комплект текущей задачи — [change-000003](viaferrata/changes/change-000003/intent.md): [Spec](viaferrata/changes/change-000003/spec.md), [Plan](viaferrata/changes/change-000003/plan.md), [Journal](viaferrata/changes/change-000003/journal.md).
- Формы и связи документов — в [руководстве шаблонов](templates/README.md), термины — в [глоссарии](docs/GLOSSARY.md).
- Перед изменениями проверь ветку, Git status и diff. Сохраняй пользовательские изменения; работай в пределах текущего репозитория и согласованного scope.

## Правила работы

- Пиши документы по-русски; стандартные заголовки, поля и ID сохраняй по шаблонам.
- Используй Plan как единственный checklist, Journal — для основания согласования, продолжения и результатов. Не создавай дополнительные документы ради формы.
- Согласуй новые обязательства и расширение scope; технические детали внутри принятого контракта решай самостоятельно.
- Храни временные данные в игнорируемой `.viaferrata/`.
- Перед установкой зависимостей и удалением файлов получи явное разрешение; действующие разрешения текущей задачи проверяй в Journal.
- Коммиты оформляй по Conventional Commits на английском: заголовок о выполненном изменении, при необходимости тело из 2–3 предложений.
- Коммит, публикация и выпуск требуют отдельного поручения.

## Проверки

После изменения кода выполни `npm run lint:fix`, затем `npm run format`. Заверши автоисправления до итоговых проверок.

Обязательный набор перед завершением задачи:

```sh
npm ci
npm run lint
npm run format:check
npm run typecheck
npm run test:all
npm run build
node bin/vf.ts validate
npm audit
npm audit --omit=dev
git diff --check
git diff --cached --check
```

Сверь tracked/untracked-файлы со scope и проверь очистку временных данных тестов. Новые исключения из проверок требуют конкретного основания. High/critical устрани либо получи принятие конкретного риска; остальные замечания разбери в Journal.

После изменения входов повтори затронутые проверки. Запиши фактические результаты и ограничения в Journal; отсутствующая или неуспешная проверка не считается пройденной. `validate` не подтверждает человеческое согласование или завершение задачи.
