# ViaFerrata

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

ViaFerrata помогает сохранять связь между намерением, требованиями, реализацией и проверками и продолжать работу между сессиями. Пилот рассчитан на одного разработчика; документы ведёт агент, формальные условия проверяет CLI.

Первый CLI `0.1.0` предоставляет help/version, `init`, `new` и базовый `validate`. Проверенная среда пилота — Node.js 24.x, npm, Linux. Пакет пока не опубликован.

## Запуск из исходников

```sh
npm ci
node bin/vf.ts --help
node bin/vf.ts --version
node bin/vf.ts --root /path/to/project init --profile lite
node bin/vf.ts --root /path/to/project new "Название задачи"
node bin/vf.ts --root /path/to/project validate
npm run typecheck
npm test
```

Перед new/validate выполните init с принятым профилем либо используйте существующий `viaferrata.toml` в корне целевого проекта. Минимальная конфигурация:

```toml
profile = "lite"
# documents_root = "viaferrata" # значение по умолчанию
```

Одна настройка documents_root меняет общий каталог; внутри него фиксированы changes/, specs/, research/, adr/. Без `--root` используется только текущий рабочий каталог (cwd); родительские каталоги не просматриваются. Строка documents_root только из пробелов недопустима; остальные пути с пробелами сохраняются дословно. Некорректная конфигурация и неподдерживаемые непустые required_checks/protected_paths останавливают команду.

New создаёт ровно три draft-документа — Intent, Spec и Plan — с ID и UTC-датой. Пакет поставляет **полноценные библиотечные формы** с optional-комментариями HTML и YAML. Агент заполняет применимые части, удаляет неприменимые блоки и исправляет связанные ссылки. Оставшиеся активные `TODO(VF)` диагностируются; создание черновика не означает его согласования. Шаблоны Journal, SRS, Research и ADR также поставляются в пакете; агент использует их по необходимости. New их не создаёт. Journal появляется с началом Implement. Обновление пакета не перезаписывает созданные артефакты.

Validate проверяет метаданные, ID, базовые разделы и объявления, существование ссылок во всех четырёх документных подкаталогах. Непосредственный каталог `changes/change-NNNNNN` с номером 000001–999999 требует Intent/Spec/Plan, даже если пока пуст; отсутствие документа даёт E_STRUCTURE. Проект без таких каталогов допустим. Validate ничего не записывает. Код 0 означает успех заявленных проверок, 1 — ошибки документов, 2 — ошибку запуска/конфигурации/IO или неподдерживаемое условие. Проверки, предусмотренные профилями `lite` и `strict`, реализованы не полностью: матрица отношений, покрытие, scope/diff, approval/evidence и завершение ещё не проверяются.

## Подключение проекта

```sh
vf --root /path/to/project init --profile lite
vf --root /path/to/project init
```

Целевой каталог должен существовать. Без `--root` используется только cwd; Git-репозиторий не требуется. Для новой конфигурации профиль `lite` или `strict` выбирается явно через `--profile`. При существующей конфигурации флаг можно опустить; несовпадающий профиль даёт ошибку. Init сохраняет конфигурацию побайтно, включая комментарии. Для нестандартного documents_root агент заранее задаёт путь в конфигурации; команда не переносит документы и не снимает ограничения required_checks/protected_paths.

Первое подключение создаёт или дополняет только `viaferrata.toml`, `AGENTS.md` и `.gitignore`. README и проектные документы сохраняются; пустые каталоги документов и сама `.viaferrata/` не создаются. В AGENTS добавляется короткая навигация между `<!-- viaferrata:begin -->` и `<!-- viaferrata:end -->`. Инструкции и формы остаются в установленном пакете: `vf --help` и успешный init показывают абсолютные пути к instructions/workflow.md и templates/README.md. Эти пути не записываются в проект. Если vf отсутствует в PATH, используйте путь к установленному bin из примера локальной поставки ниже.

Повторный init сохраняет готовые файлы, их байты и mtime. Проектные дополнения размещайте вне блока ViaFerrata. Изменённый, повторный или неполный блок останавливает команду с E_EXISTS: агент проверяет различие и сохраняет ручные дополнения вне блока либо согласует восстановление. Автоматической перезаписи блока и команды update нет.

Init добавляет в конец `.gitignore` правило `/.viaferrata/`, если самостоятельной строки `/.viaferrata/` или `.viaferrata/` ещё нет. Если подходящая строка есть, файл сохраняется. Исключение: любое правило с начальным `!` после последнего такого исключения даёт E_EXISTS, даже если отрицание относится к другому пути. Это ограничение простого алгоритма; агент проверяет порядок и размещает исключение после отрицаний. Остальные байты сохраняются; LF/CRLF и UTF-8 BOM поддерживаются. Init не меняет Git index: ранее tracked временные данные требуют отдельного решения.

До записи проверяются все планируемые изменения и доступность инструкций. Симлинки в проверяемых путях не поддерживаются. При ошибке IO команда возвращает код 2, называет проблемный путь и выполненные изменения; уже добавленные файлы автоматически не удаляются. После исправления причины повторите init: готовые части сохранятся, отсутствующие будут добавлены. Существующие файлы заменяются только после подготовки полной версии; управляемый сбой записи не обрезает прежний текст. Защита от злонамеренных конкурентных подмен и транзакционность при сбое питания не заявляются.

Код 0 означает готовность подключения, включая повтор без изменений; ошибки init дают 2 и диагностику в stderr с путём, причиной и способом исправления. Согласование, смысловая полнота и завершение задачи этим не подтверждаются. Следующий шаг — new, заполнение документов агентом и validate; незаполненный черновик должен диагностироваться.

## Локальная поставка

```sh
npm pack
npm install --omit=dev --ignore-scripts --prefix /path/to/installation /absolute/path/to/viaferrata-0.1.0.tgz
/path/to/installation/node_modules/.bin/vf --help
```

Обычный `npm pack` выполняет `prepack`: проверяет типы и собирает JavaScript в `dist/`. `npm run build` удаляет предыдущий `dist/`, проверяет весь собственный код и компилирует только bin/src. При ошибке типов сборка и обычная упаковка завершаются с ошибкой. В Git каталог `dist/` не хранится.

Если lifecycle scripts отключены при упаковке, сборку нужно выполнить явно непосредственно перед ней:

```sh
npm run build && npm pack --ignore-scripts
```

Сам `npm pack --ignore-scripts` пропускает сборку и может упаковать устаревший или отсутствующий `dist/`. Установленный `vf` запускает `dist/bin/vf.js` обычным Node.js 24; TypeScript и остальные зависимости разработки потребителю не нужны. Отключение lifecycle scripts при установке не мешает работе готового пакета.

CLI читает схемы и шаблоны из установленного пакета. Общие инструкции поставляются рядом и предназначены для исполнителя. Конфигурация и документы принадлежат целевому проекту. Тест проверяет tarball при недоступном каталоге, из которого был собран пакет; проверяется сценарий help/version → init → new → validate. Реальный второй проект остаётся отдельным испытанием.

Оба руководства поставляются вместе с пакетом. Каталог instructions предназначен прежде всего для агента; локальный AGENTS.md задаёт особенности проекта. Агент заполняет документы по ним; CLI не исполняет текст инструкций и не подтверждает согласование.

В исходном репозитории `docs/GLOSSARY.md` содержит справочник терминов проекта. Каталог `docs/` предназначен для документации с возможной последующей сборкой и публикацией; он не входит в npm-пакет. Сборка и публикация документации пока не настроены.

## Проверка исходников

Обязательные команды разработки: `npm ci`, `npm run typecheck`, `npm test` и `npm run build`. Они запускаются из исходного репозитория. `node bin/vf.ts --root . validate` проверяет структуру собственных документов. Для установки зависимостей и теста поставки нужен доступ к npm registry. Тест собирает временную копию исходников, затем устанавливает tarball обычным npm install с `--omit=dev --ignore-scripts` и новым изолированным кешем; предварительно наполнять пользовательский кеш не требуется. Отсутствие сети или другая ошибка установки означает непройденную проверку.

Тестовые проекты, кеш установки и временная копия пакета находятся в `/tmp/vf-test-*` и удаляются после теста. Исходные фикстуры не изменяются. После установки источник упаковки становится недоступным, а установленный CLI выполняет help/version/init/new/validate из постороннего cwd. Проверяются повторный init, перенос установки, диагностика незаполненного черновика и успех независимого заполненного примера. Для sandbox-сред может потребоваться разрешение на subprocess и сеть.

Исходники разделены по ответственности: `src/cli/` разбирает аргументы и формирует вывод, `src/commands/` выполняет сценарии команд, `src/documents/` читает и разбирает документы, строит индекс и проверяет связи. Общие модели документов находятся в `src/documents/types.ts`; типы конфигурации и диагностик — рядом с соответствующей реализацией. Парсеры YAML и Markdown принимают текст и возвращают данные и диагностику отдельно от файловых операций.

CLI, тесты и служебные скрипты написаны на TypeScript ESM и запускаются напрямую в Node.js 24 без предварительной сборки и дополнительного загрузчика. Node удаляет аннотации, но не проверяет типы: для этого отдельно выполняется `npm run typecheck` в строгом режиме. Для проверки типов и сборки зафиксирован TypeScript 7.0.2; бандлер не используется. Тесты работают через встроенный node:test; проверки данных YAML/TOML/Markdown при выполнении сохранены. Необязательный `node scripts/input-manifest.ts` выводит SHA-256 входов, включая обе конфигурации tsc; `dist/` исключён из манифеста. `.viaferrata/` предназначена для временных логов, кешей и диагностических манифестов вне Git; необходимые команды, результаты и ограничения сохраняются в Journal. Постоянный пофайловый манифест для каждой задачи не требуется. Проверки, собственные changes и результаты разработки не поставляются в npm-пакете.
