# ViaFerrata

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

ViaFerrata помогает сохранять связь между намерением, требованиями, реализацией и проверками и продолжать работу между сессиями. Пилот рассчитан на одного разработчика; документы ведёт агент, формальные условия проверяет CLI.

Первый CLI `0.1.0` предоставляет help/version, `new` и базовый `validate`. Проверенная среда пилота — Node.js 24.x, npm, Linux/WSL2. Пакет пока не опубликован.

## Запуск из исходников

```sh
npm ci
node bin/vf.js --help
node bin/vf.js --version
node bin/vf.js --root /path/to/project new "Название задачи"
node bin/vf.js --root /path/to/project validate
npm test
```

Перед new/validate агент создаёт в корне целевого проекта `viaferrata.toml` с принятым профилем. Минимальный пример:

```toml
profile = "lite"
# documents_root = "viaferrata" # значение по умолчанию
```

Одна настройка documents_root меняет общий каталог; внутри него фиксированы changes/, specs/, research/, adr/. Без `--root` используется только текущий рабочий каталог (cwd); родительские каталоги не просматриваются. Init остаётся отдельной следующей возможностью. Строка documents_root только из пробелов недопустима; остальные пути с пробелами сохраняются дословно. Некорректная конфигурация и неподдерживаемые непустые required_checks/protected_paths останавливают команду.

New создаёт ровно три draft-документа — Intent, Spec и Plan — с ID и UTC-датой. Пакет поставляет **полноценные библиотечные формы** с optional-комментариями HTML и YAML. Агент заполняет применимые части, удаляет неприменимые блоки и исправляет связанные ссылки. Оставшиеся активные `TODO(VF)` диагностируются; создание черновика не означает его согласования. Шаблоны Journal, SRS, Research и ADR также поставляются в пакете; агент использует их по необходимости. New их не создаёт. Journal появляется с началом Implement. Обновление пакета не перезаписывает созданные артефакты.

Validate проверяет метаданные, ID, базовые разделы и объявления, существование ссылок во всех четырёх документных подкаталогах. Непосредственный каталог `changes/change-NNNNNN` с номером 000001–999999 требует Intent/Spec/Plan, даже если пока пуст; отсутствие документа даёт E_STRUCTURE. Проект без таких каталогов допустим. Validate ничего не записывает. Код 0 означает успех заявленных проверок, 1 — ошибки документов, 2 — ошибку запуска/конфигурации/IO или неподдерживаемое условие. Проверки, предусмотренные профилями `lite` и `strict`, реализованы не полностью: матрица отношений, покрытие, scope/diff, approval/evidence и завершение ещё не проверяются.

## Локальная поставка

```sh
npm pack
npm install --prefix /path/to/installation /absolute/path/to/viaferrata-0.1.0.tgz
/path/to/installation/node_modules/.bin/vf --help
```

CLI читает схемы и шаблоны из установленного пакета. Общие инструкции поставляются рядом и предназначены для исполнителя. Конфигурация и документы принадлежат целевому проекту. Тест проверяет tarball при недоступном каталоге, из которого был собран пакет; реальный второй проект и сценарий init ещё впереди.

## Инструкции и шаблоны

- [Общие правила работы](instructions/workflow.md).
- [Библиотечные формы, метаданные и матрица отношений](templates/README.md).

Оба руководства поставляются вместе с пакетом. Каталог instructions предназначен прежде всего для агента; локальный AGENTS.md задаёт особенности проекта. Агент заполняет документы по ним; CLI не исполняет текст инструкций и не подтверждает согласование.

В исходном репозитории `docs/GLOSSARY.md` содержит справочник терминов проекта. Каталог `docs/` предназначен для документации с возможной последующей сборкой и публикацией; он не входит в npm-пакет. Сборка и публикация документации пока не настроены.

## Проверка исходников

Команды `npm ci` и `npm test` запускаются из исходного репозитория. Для установки зависимостей и теста поставки нужен доступ к npm registry. Тест устанавливает tarball обычным npm install с новым изолированным кешем; предварительно наполнять пользовательский кеш не требуется. Отсутствие сети или другая ошибка установки означает непройденную проверку.

Тестовые проекты, кеш установки и временная копия пакета находятся в `/tmp/vf-test-*` и удаляются после теста. Исходные фикстуры не изменяются. После установки источник упаковки становится недоступным, а установленный CLI выполняет help/version/new/validate из постороннего cwd. Для sandbox-сред может потребоваться разрешение на subprocess и сеть.

Реализация использует JavaScript ESM без сборщика, встроенный node:test и библиотеки парсинга YAML/TOML/Markdown. `.viaferrata/` предназначена для временных логов, кешей и диагностических манифестов вне Git; необходимые команды, результаты и ограничения сохраняются в Journal. Постоянный пофайловый манифест для каждой задачи не требуется. Проверки, собственные changes и результаты разработки не поставляются в npm-пакете.
