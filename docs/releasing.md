# Ручной выпуск ViaFerrata

Выпуск выполняется из чистого trunk. В примерах замените `<версия>`, `<SHA>` и `<архив.tgz>` фактическими значениями. Во всех шагах используйте один и тот же проверенный архив. Отдельные change-комплект, Journal и служебный коммит для выпуска не нужны.

## 1. Подготовить изменения и слить в trunk

Согласуйте версию. Обновите package.json, соответствующие поля lockfile, примеры запуска и [CHANGELOG](../CHANGELOG.md) с датой выпуска. Опубликованные разделы не переписывайте. Git-данные для CHANGELOG собирает `npm run changelog`.

Выполните применимые [проверки проекта](../AGENTS.md#проверки), затем разрешённые коммит, push и merge. Успешные проверки неизменных входов повторять не нужно.

## 2. Собрать архив

Из чистого checkout итогового коммита trunk:

```sh
npm ci
git rev-parse HEAD
npm run release:pack
```

Сохраните показанный SHA для будущего тега. Путь к архиву возьмите из результата сборки: `.viaferrata/release/viaferrata-<версия>.tgz`. Сборка уже запускается через prepack, отдельно вызывать build не нужно.

## 3. Проверить архив

```sh
VF_TARBALL="<архив.tgz>" npm run test:package
npm run release:dry-run -- "<архив.tgz>"
```

Первая команда проверяет установку и работу пакета, выводит SHA-256 и integrity; вторая выполняет dry-run публикации. Успешную проверку неизменного архива повторять не нужно. После изменения содержимого пересоберите архив и повторите затронутые проверки.

## 4. Опубликовать

Покажите пользователю версию, SHA исходников, архив с хешем, результаты проверок и команду публикации. После подтверждения опубликуйте этот файл без пересборки:

```sh
npm run release:publish -- "<архив.tgz>"
```

Если ещё не авторизованы, перед публикацией выполните `npm login --registry https://registry.npmjs.org`. Пользователь проходит вход и 2FA самостоятельно; секреты в чат не передаются.

## 5. Проверить публикацию и оформить релиз

```sh
npm view "viaferrata@<версия>" name version dist-tags dist.integrity \
  --json --registry https://registry.npmjs.org
```

Сверьте версию, тег latest и integrity с кандидатом. Проверьте установку точной registry-версии через npx и глобальный vf с пустыми кешами и изолированным prefix. После этого создайте тег на коммите, из которого собран архив:

```sh
git tag -a "v<версия>" "<SHA>" -m "Release <версия>"
git push origin "refs/tags/v<версия>"
gh release create "v<версия>" --verify-tag --title "ViaFerrata <версия>"
```

Для gh требуется авторизация. В интерактивном создании Release укажите текст соответствующего раздела CHANGELOG и ссылки:

- npm: `https://www.npmjs.com/package/viaferrata/v/<версия>`.
- CHANGELOG: `https://github.com/ArtMan-8/ViaFerrata/blob/v<версия>/CHANGELOG.md`.

При ошибке сначала выясните, что уже опубликовано. Не повторяйте отправку вслепую и не перемещайте существующий тег. Если пакет опубликован, а создание тега или Release прервано, продолжайте только с отсутствующего действия.
