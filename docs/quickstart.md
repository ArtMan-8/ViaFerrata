# Первое подключение ViaFerrata

ViaFerrata поставляет CLI, инструкции агенту и шаблоны. Человек задаёт цель и принимает существенные решения; агент готовит документы, вызывает CLI и проверяет изменение. CLI не вызывает модель и не заменяет среду агента.

## Среда и способ запуска

Нужны Node.js 24.x и npm. Пользовательский сценарий проверен на Linux x86_64; поддержка других ОС пока не подтверждена.

Выберите один из двух равноправных способов:

| Способ        | Установка и проверка                                    | Следующие вызовы                 |
| ------------- | ------------------------------------------------------- | -------------------------------- |
| Npx           | `npx viaferrata@0.1.0 --version`                        | `npx viaferrata@0.1.0 <команда>` |
| Глобальный vf | `npm install -g viaferrata@0.1.0`, затем `vf --version` | `vf <команда>`                   |

Сообщите агенту выбранный способ и версию. Примеры далее используют npx; при глобальной установке заменяйте `npx viaferrata@0.1.0` на `vf`.

## Подключение проекта

Целевой каталог должен существовать. Сначала получите пути к инструкциям из текущей установки, затем подключите проект:

```sh
npx viaferrata@0.1.0 --help
npx viaferrata@0.1.0 init /path/to/project --profile lite
cd /path/to/project
```

Init создаёт viaferrata.toml, добавляет блок навигации в AGENTS.md и исключение временного каталога в .gitignore. Пользовательские данные сохраняются. Без path используется текущий каталог; при первом подключении профиль lite или strict указывается явно. Первое подключение внутри уже подключённого проекта запрещено.

Профиль strict не означает, что весь предусмотренный контроль реализован. Текущие ограничения перечислены в [README](../README.md#ограничения).

## От цели до проверки

Откройте подключённый проект в среде агента. Сообщите цель и способ запуска ViaFerrata. Агент читает локальные правила, получает пути к инструкциям через help и выбирает соразмерную формализацию задачи.

Для deep-задачи агент создаёт черновики:

```sh
npx viaferrata@0.1.0 new "Название изменения"
npx viaferrata@0.1.0 validate
```

New создаёт Intent, Spec и Plan в новом каталоге changes внутри documents_root. Validate сразу после new ожидаемо завершается с кодом 1: незаполненные placeholder требуют работы агента. Это не ошибка установки. Агент заполняет документы по [руководству шаблонов](../templates/README.md), удаляет неприменимые необязательные части и согласует с вами цель, требования и план. Файлы не нужно заполнять вручную ради процесса.

При начале реализации агент создаёт Journal из поставляемого шаблона, ведёт Plan как единственный checklist и сохраняет фактические проверки. После заполнения снова вызывает validate. Успешный validate подтверждает только поддерживаемую структуру; согласование, правильность поведения и завершение требуют отдельных оснований и проверок проекта.

Для простой vibe-задачи отдельный комплект и new не обязательны. Правила проекта и применимые проверки сохраняются.

Команды new и validate ищут ближайший viaferrata.toml вверх от текущего каталога. Поэтому их можно вызывать из подкаталога проекта. Ошибочная ближайшая конфигурация останавливает поиск; CLI не выбирает другую конфигурацию ради успешного результата. Параметра --root нет. Поля protected_paths и required_checks с непустыми значениями пока не поддерживаются; не очищайте их ради прохождения проверки.

## Повтор init и конфликты

Повторите подключение без выбора нового профиля:

```sh
npx viaferrata@0.1.0 init /path/to/project
```

Готовые файлы сохраняются без изменения байтов и времени модификации. Прежние штатные формы блока ViaFerrata в AGENTS.md также принимаются без переписывания. Если внутри блока есть ручная содержательная правка, init сообщает конфликт. Сохраните дополнения вне блока и разрешите различие перед повтором; автоматической перезаписи через force нет.

При сбое записи исправьте указанную причину и повторите init. Уже подготовленные части сохраняются; сообщение сообщает о выполненных изменениях. При ошибках использования или доступа CLI возвращает код 2.

## Продолжение в новой сессии

Передайте агенту каталог проекта, задачу и выбранный способ запуска: npx с версией или глобальный vf. Агент повторяет help этим способом, открывает актуальные пути инструкций и обнаруживает комплект по [общим правилам](../instructions/workflow.md#обнаружение-задачи).
