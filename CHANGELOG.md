# CHANGELOG

Изменения ViaFerrata для пользователей.

## 0.2.0 — 2026-11-26

### Переход с 0.1.0

- В скриптах и инструкциях замените `vf new "Название"` на `vf new change "Название"`. Тип документа теперь обязателен.
- Уберите `protected_paths` из конфигурации проекта. Для deep-задач разрешённые пути задаются в Spec.
- Дельты требований к SRS теперь записываются в YAML. Для существующих документов см. [правила перехода](https://github.com/ArtMan-8/ViaFerrata/blob/trunk/templates/README.md#дельта-требований).

### Новые возможности

- При первом подключении `vf init --documents-root <path>` позволяет выбрать каталог документов. Команды `vf new srs`, `vf new adr` и `vf new research` создают отдельные документы.
- `vf scope` сверяет изменения в Git с согласованными путями. `vf summary` показывает результаты проверок из Journal или отчёта, переданного через стандартный ввод.
- `vf validate` проверяет связи между документами, включая структурное покрытие требований. `vf complete` проверяет условия завершения deep-задачи и отмечает её выполнение в Plan.
- Инструкции описывают выбор между `vibe` и `deep`, продолжение работы по Journal, перенос принятых требований в SRS и архивирование завершённых изменений.

## 0.1.0 — 2026-11-15

Первый выпуск.

### Новые возможности

- CLI `vf` с командами `init`, `new` и `validate`, справкой и выводом версии. Запуск через `npx viaferrata@0.1.0` или глобально установленный `vf`; требуется Node.js 24.x.
- Подключение существующего каталога через `vf init [path] --profile lite|strict`: конфигурация `viaferrata.toml`, навигация для агента в AGENTS.md и исключение временного каталога `.viaferrata/` из Git. Повторный init сохраняет штатное подключение и ручной текст вне управляемого блока; конфликтующие изменения блока требуют явного разрешения.
- Создание черновиков Intent, Spec и Plan командой `vf new "Название задачи"`. Комплекты получают шестизначные ID и хранятся в каталоге документов проекта.
- Базовая структурная проверка метаданных, ID, обязательных разделов, placeholders и ссылок командой `vf validate` без изменения проверяемых документов.
- Поиск ближайшего `viaferrata.toml` вверх от рабочего каталога для new и validate. Ошибка ближайшей конфигурации останавливает поиск; первое подключение внутри уже подключённого проекта запрещено.
- Инструкции агенту и семь шаблонов: Intent, Spec, Plan, Journal, SRS, Research и ADR. Процесс разделяет формализацию задачи `vibe/deep` и профиль контроля `lite/strict`, сохраняет основания решений и результаты проверок для продолжения работы.
- [Руководство по началу работы](https://github.com/ArtMan-8/ViaFerrata/blob/trunk/docs/quickstart.md) и навигация к инструкциям через help, включая продолжение в новой агентной сессии. Руководство доступно в репозитории; каталог docs не поставляется. Пакет содержит собранный JavaScript, инструкции и шаблоны; зависимости разработки для запуска не требуются.

### Ограничения

Полный контроль профилей lite/strict, runner, автоматические approval/evidence и проверки scope/diff/finish пока не реализованы. Успешный validate не подтверждает человеческое согласование, полноту требований или правильность поведения программы. Обновление пакета не перегенерирует документы проекта.
