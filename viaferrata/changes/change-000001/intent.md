# Первый CLI ViaFerrata

## Goal

Дать исполнителю ViaFerrata команды для создания следующего deep-комплекта и обнаружения базовых формальных ошибок документов без ручного переноса ID и дат пользователем. Правила и результаты должны быть доступны в одном репозитории, проверка поставки — воспроизводима с новым кешем.

## Constraints

Реализация начинается после принятия этого Intent, Spec и Plan. В первой задаче только help/version, new и базовый validate. Пилот — Node.js 24.x на Linux/WSL2, рекомендуемый профиль проекта — lite. Первая версия не обеспечивает полностью ни lite, ни strict. Правила процесса действуют независимо от наличия автоматизации. Чужие документы сохраняются. Init, публикация, runner/evidence, автоматическое завершение и контроль diff не входят в задачу.

ADR и Research создаются только при содержательной необходимости.

## Context

ViaFerrata ведёт собственный комплект документов в этом репозитории. Проверки валидатора опираются на независимые документы и заранее заданные ожидания. CLI поставляется с семью библиотечными формами и инструкциями; глоссарий docs/GLOSSARY.md относится к документации репозитория и не входит в npm-пакет.

## Acceptance Criteria

### AC-1: CLI запускается в установленной среде

После установки зависимостей запуск по пути выводит help с доступными командами и версию из package.json. Неверная команда возвращает диагностируемую ошибку. Help/version работают без конфигурации проекта.

- Covers:
  - [change-000001/spec/R-1]
- Verification: subprocess-тесты help/version/неизвестной команды из временного cwd без конфигурации; сравнить версию с package.json.

### AC-2: Целевой проект определяется однозначно

`--root` направляет new/validate только в указанный проект; без него требуется конфигурация непосредственно в cwd. Отсутствующая, повреждённая или неподдерживаемая конфигурация даёт ошибку до записи. Соседний проект и исходная директория пакета не изменяются.

- Covers:
  - [change-000001/spec/R-2]
- Verification: тесты двух временных проектов, стандартного и изменённого documents_root, запуска из вложенной/посторонней директории, пути с пробелами, ошибок TOML, неизвестных ключей и недопустимых корней; сравнить деревья до/после.

### AC-3: New создаёт безопасный черновик

New выбирает следующий свободный ID, создаёт ровно intent.md, spec.md, plan.md с общим префиксом, датами и начальными состояниями. Существующие файлы сохраняются побайтно. Journal отсутствует. Шаблонные места явно помечены, не содержат выдуманных требований или согласования и диагностируются при validate до заполнения агентом.

- Covers:
  - [change-000001/spec/R-3]
- Verification: проверить пустой проект, пропуск занятых номеров, конфликт пути, неправильный индекс ID, исчерпание диапазона и сбой записи после первого файла. Ожидания метаданных заданы отдельно от валидатора; проверка new → validate — лишь дополнительная.

### AC-4: Ошибки метаданных и структуры обнаруживаются

Независимые корректные документы проходят заявленные проверки. Повреждённый YAML, неверные/дублирующиеся ID, недопустимые состояния и даты, поля в неверном типе документа, отсутствующие обязательные разделы и объявления получают диагностику с местом и причиной. Необязательные пустые разделы не требуются.

- Covers:
  - [change-000001/spec/R-4]
  - [change-000001/spec/R-5]
- Verification: статические фикстуры из tests/fixtures/validation и отдельные тесты оставшихся правил схемы; сверить ожидаемые коды и позиции без вызова генератора.

### AC-5: Ссылки проверяются во всём объявленном охвате

Полный проход обнаруживает отсутствующий документ или локальный элемент, включая удалённую цель неизменённой входящей ссылки. Примеры в коде, комментарии, обычные упоминания и внешние Markdown-ссылки не создают ложных логических ссылок. Диагностика дубликата документного ID указывает оба места.

- Covers:
  - [change-000001/spec/R-5]
  - [change-000001/spec/R-6]
- Verification: независимые фикстуры, удаление адресата при неизменном исходном документе, цели в SRS/ADR/Research, повторный локальный ID, ссылки в коде и обычном тексте.

### AC-6: Проверка ничего не исправляет и не скрывает ограничения

Два запуска validate не меняют байты, состав файлов и mtime документов. Отчёт называет выполненные проверки и недоступный контроль. Структурный успех при `approved` или `completed` не называется подтверждением решения, evidence или завершения. Настройка strict не превращается в lite.

- Covers:
  - [change-000001/spec/R-7]
- Verification: снимки деревьев до/после двух запусков, тесты отчёта для lite/strict, approved без основания и completed без evidence; проверить exit codes и отсутствие записи в .viaferrata/.

### AC-7: Пакет хранит собственные ресурсы

CLI читает шаблоны относительно установленного пакета, проектные документы — относительно выбранного корня. Общие инструкции предназначены агенту и поставляются рядом. Состав локального tarball включает исполняемые файлы, схемы, шаблоны и инструкции; тестовые проекты и рабочие логи в него не входят. Обновление исходного шаблона не меняет уже созданный change.

- Covers:
  - [change-000001/spec/R-8]
- Verification: npm pack --dry-run --json, локальная упаковка/установка в отдельную директорию и запуск help/new/validate без доступа к исходной директории пакета; сравнить ранее созданный документ после изменения копии шаблона. Init и второй реальный проект не входят в проверку.

### AC-8: Собственный комплект проверен независимым от самопроверки способом

Все обязательные тесты проходят, заполненный change-000001 проходит структурную проверку. В Journal сохранены фактические команды, входы/версии, результаты и ограничения; результат не обосновывается только совпадением генератора и валидатора.

- Covers:
  - [change-000001/spec/R-7]
  - [change-000001/spec/R-8]
- Verification: npm ci, npm test, запуск validate на репозитории; ручная сверка контракта с diff и независимых ожиданий фикстур.

### AC-9: Документация самодостаточна

Правила и матрица отношений доступны внутри репозитория и пакета; все семь форм поставляются отдельными файлами. Документы не требуют отсутствующих источников. Journal содержит краткое основание согласования, текущее состояние и актуальные результаты проверок с указанием входов и ограничений, без полных копий других артефактов и хронологии правок.

- Covers:
  - [change-000001/spec/R-9]
- Verification: проверить локальные ссылки исходников и пакета; вручную сверить текстовые отсылки, основание согласования и соответствие результатов проверенным входам.

### AC-10: Пограничные случаи имеют однозначный результат

Пустой каталог комплекта диагностируется; конфигурация с documents_root только из пробелов отклоняется до записи. Обычные пути с пробелами, пустой проект и выделение следующего ID сохраняют поведение.

- Covers:
  - [change-000001/spec/R-10]
- Verification: subprocess-тесты пустого/неполного комплекта, пустого проекта, обоих вариантов пути и неизменности файлов при отказе.

### AC-11: Проверки и входы воспроизводимы

Установка tarball проверяется с новым изолированным кешем и недоступным источником упаковки. Команды, среда, результаты и ограничения сохраняются в Journal. Постоянный манифест не требуется; по необходимости диагностический скрипт воспроизводимо вычисляет отпечатки точных входов.

- Covers:
  - [change-000001/spec/R-11]
  - [change-000001/spec/R-12]
- Verification: npm ci с новым кешем, npm test, проверка диагностического скрипта и игнорирования временного состояния, обязательные проверки и сверка scope.
