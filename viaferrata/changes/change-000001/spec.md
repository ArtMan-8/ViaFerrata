# Контракт первого CLI

## Change Boundaries

Входят npm-пакет с help/version, new и базовым validate, семь библиотечных форм, инструкции, глоссарий docs/GLOSSARY.md и независимые тесты. Поля/ID и матрица отношений описаны в [локальном руководстве](../../../templates/README.md); интерфейсы, диагностика, охват парсера и схема конфигурации определены ниже.

Собственные четыре артефакта change включены в scope автоматически; остальные разрешённые пути перечислены в метаданных. Для этой задачи `/**` означает содержимое каталога на любой глубине; это договорённость о путях, не реализация glob-движка. Изменения LICENSE, файлов вне репозитория и иных changes запрещены. Fixtures являются тестовыми данными внутри tests и не входят в процессный индекс проекта.

Не входят init, update, автоматическое approval/evidence, запуск инженерных проверок из vf, finish, контроль всего diff, покрытие, циклы отношений, графовые инструменты, hooks, миграции, конкурентное выделение ID и публикация. Каталог docs предназначен для документации с возможной последующей сборкой и публикацией и не входит в npm-пакет; настройка его сборки и публикация также вне задачи.

## Requirements

### R-1: Пакет и интерфейс

JavaScript ESM, Node.js 24.x (`engines.node: >=24 <25`), npm, Linux/WSL2. Локальное имя `viaferrata`, версия `0.1.0`, `private: true`, bin `vf` → `bin/vf.js`. Транспиляция не нужна. Поддерживаются:

```text
vf --help
vf --version
vf [--root PATH] new "Название задачи"
vf [--root PATH] validate
```

Без аргументов выводится help, код 0. Неизвестная команда, лишний аргумент, неизвестный/повторный флаг, пустое название или название с переводом строки — E_USAGE, код 2. Название используется только в H1 документов, не в пути; Markdown-метасимволы экранируются. Версия берётся из package.json, не дублируется в конфигурации. Help/version не читают конфигурацию. Вне Node 24 запуск завершается понятной ошибкой runtime, код 2.

### R-2: Корень и конфигурация

Путь, переданный через `--root`, абсолютен либо разрешается относительно текущего рабочего каталога (cwd). Без флага корень — cwd. Поиск в родительских каталогах и автоматический выбор Git-root не выполняются; установленный пакет не задаёт корень проекта. Корень должен существовать. `viaferrata.toml` обязателен для new/validate. При отсутствии `viaferrata.toml` возвращается E_CONFIG; запись не выполняется. Пример минимальной конфигурации после принятия lite:

```toml
profile = "lite"
```

Схема конфигурации:

| Ключ            | Тип и правило                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ |
| profile         | Обязательная строка lite или strict; не меняется командой.                                                               |
| documents_root  | Строка, по умолчанию `viaferrata`. Общий путь документов относительно корня проекта.                                     |
| protected_paths | Массив строк, по умолчанию пуст. Непустой в этом срезе → E_UNSUPPORTED до new/validate: glob-контроль ещё не реализован. |
| required_checks | Массив строк, по умолчанию пуст. Непустой → E_UNSUPPORTED: runner ещё отсутствует.                                       |

Одна настройка задаёт общий корень. В нём фиксированы подкаталоги `changes/`, `specs/`, `research/`, `adr/`; отдельных настроек путей для типов в первом срезе нет. Например, `documents_root = "process"` задаёт process/ как место хранения всех четырёх категорий. Изменение настройки само по себе не переносит существующие файлы; автоматической миграции в этом срезе нет.

```text
viaferrata.toml
viaferrata/
  changes/change-NNNNNN/
  specs/
  research/
  adr/
.viaferrata/                # временное состояние вне Git
```

Конфигурация остаётся в корне проекта. Каталог documents_root содержит версионируемые документы и не исключается из Git; `.viaferrata/` сохраняет отдельное назначение временного состояния. Сами подкаталоги появляются по необходимости, пустые specs/research/adr не создаются ради структуры.

Неизвестные ключи, неверные типы, повторные ключи и повреждённый TOML → E_CONFIG. documents_root — непустой относительный путь каталога с `/`; абсолютные пути, `.`/`..`-сегменты, обратные слеши и glob запрещены. Служебные .git/.viaferrata/node_modules не используются как его сегменты. Отсутствующий документный подкаталог считается пустым; new может создать общий корень и его changes/. Симлинк в корне проекта, конфигурации, общем корне, пути документного подкаталога или обнаруженном документе → E_UNSUPPORTED; обход наружу не выполняется. Эти ограничения охвата не заменяют будущий scope-контроль.

Рабочая конфигурация этого репозитория содержит `profile = "lite"`, без дополнительных required_checks и protected_paths. Ограничения среды и scope действуют независимо от этих настроек.

### R-3: Создание change

Все обычные `.md` в четырёх документных корнях индексируются по ID для выделения номера. Дополнительно занятыми считаются непосредственные пути `change-NNNNNN` в changes, в том числе неполные каталоги и обычные файлы. Используется max занятого номера + 1, начиная с 000001; пропуски в нумерации не заполняются. Шесть цифр, диапазон 000001–999999; после 999999 — E_ID_EXHAUSTED. Ошибка чтения/YAML/ID или дубликат ID в индексе блокирует new до записи; содержательные TODO старых черновиков не блокируют выделение номера. Полностью удалённую историю CLI не восстанавливает: агент сохраняет исторические комплекты и не переиспользует известные выведенные ID.

New создаёт `<documents_root>/changes/change-NNNNNN` и ровно три файла по templates. Все ID совпадают с назначением файлов, status draft, Plan execution not_started. created и updated — одна текущая календарная дата UTC в кавычках; служебные значения подставляет инструмент. Journal не создаётся. Начальный Spec может не иметь scope: разрешены лишь четыре собственных артефакта до явного расширения. `TODO(VF)` в содержании обозначает работу агента; это не готовые требования и не согласование. Validate такого черновика возвращает E_DRAFT_PLACEHOLDER.

Каталог и файлы создаются исключительно без перезаписи (exclusive create). Конфликт после выбора ID → E_EXISTS; повторного скрытого выбора ID нет. До первой записи проверяются конфигурация, индекс и доступность шаблонов. При ошибке записи → E_IO с перечнем фактически созданных путей. Частичный результат сохраняется для диагностики, автоматического удаления нет; следующий запуск считает номер занятым. Защита от конкурентных злонамеренных изменений файловой системы и транзакционность при сбое питания не заявляются.

### R-4: YAML и идентичность

Validate читает UTF-8 Markdown с YAML front matter между отдельными строками `---` в начале файла (допустим UTF-8 BOM). Принимаются LF/CRLF. YAML 1.2; верхний уровень — mapping, дубликаты ключей, пользовательские tags, aliases/anchors и merge keys не поддерживаются и диагностируются. Неверный синтаксис → E_YAML; неподдерживаемая YAML-конструкция → E_UNSUPPORTED.

ID: `change-[0-9]{6}/(intent|spec|plan|journal)`, `srs-[0-9]{6}`, `research-[0-9]{6}`, `adr-[0-9]{6}`, номер 000001–999999. Нет/неверен id → E_ID; тип по имени файла не угадывается. Документные ID уникальны в пределах всего индекса; дубликат → E_DUPLICATE_ID с обоими путями. Документы change размещаются в `<documents_root>/changes/change-NNNNNN/{intent,spec,plan,journal}.md` с согласованными ID; иное размещение → E_LOCATION. Самостоятельные документы имеют произвольные имена внутри соответствующего корня. Дополнительный Markdown без ID в документном корне — E_ID, поэтому README и примеры хранятся вне этих корней.

Для каждого change обязательны Intent/Spec/Plan. По процессу Journal возникает с началом Implement; генератор его не создаёт. Этот срез не устанавливает фактический момент его создания, но проверяет наличие Journal при execution in_progress/blocked/completed; отсутствие → E_STRUCTURE. Проверка истинности перехода не выполняется. Отсутствие одного из первых трёх документов → E_STRUCTURE.

created/updated обязательны: строковые скаляры в кавычках, реальная календарная дата YYYY-MM-DD, updated >= created, иначе E_DATE. Обязательный status: Intent/Spec/Plan/ADR/SRS — draft/approved/superseded/cancelled; Research — draft/completed/superseded/cancelled. Journal не имеет status. Execution обязателен только Plan: not_started/in_progress/blocked/completed/cancelled. Неверное значение → E_ENUM; отсутствующее обязательное поле, неверный тип или запрещённое размещение → E_FIELD.

Scope — только Spec, опциональный непустой массив непустых строк; glob здесь не интерпретируется. Origin/research/adr/supersedes — опциональные непустые массивы строк адресов без квадратных скобок, блочная запись через дефисы. Research указывает документ research, adr — документ adr. Supersedes допустим в Intent/Research/ADR и адресует документ того же типа; другие применения остаются неподдерживаемыми (E_UNSUPPORTED), не объявляются новым запретом модели. Origin допускает адрес комплекта, документа или элемента. Type/kind/change_id запрещены (E_FIELD). Неизвестное поле документа → W_UNKNOWN_FIELD: сохранено, не интерпретировано; это предупреждение не даёт утверждать полную проверку расширения. Неизвестные поля конфигурации обрабатываются иначе, по R-2.

### R-5: Минимальная Markdown-грамматика

Один H1 с непустым заголовком. Стандартные H2 обязательны: Intent — Goal, Constraints, Context, Acceptance Criteria; Spec — Change Boundaries, Requirements, Definition of Done; Plan — Steps; Journal — Current State, Significant Events, Verification and Result. Scenarios, Examples, Technical Approach опциональны. SRS — Purpose and Boundaries, Requirements. Структура тела Research/ADR этим срезом не проверяется. Дубликат обязательного H2 или его отсутствие → E_STRUCTURE; проверка смысловой достаточности разделов остаётся агенту.

Объявления находятся вне code/inlineCode, HTML-комментариев и blockquote:

- H3 `AC-N: название` в Acceptance Criteria Intent; минимум один AC, под каждым строка списка `- Verification: непустой текст`.
- H3 `R-N: название` в Requirements Spec/SRS, `S-N: название` в Scenarios Spec/SRS; R в задачной Spec не обязателен для lite, S всегда опционален. В SRS минимум один R.
- H3 `DOD-N: название` в Definition of Done Spec; опционально.
- H3 `W-N: название` в Steps Plan, затем строка `Execution: sequential` либо `Execution: parallel` и шаги `- [ ] P-N: текст` / `- [x] P-N: текст`; минимум одна волна и один шаг в каждой. Все P-ID уникальны в Plan.
- H4 `V-N: название` в подразделе H3 Verification внутри Verification and Result Journal; V необязателен до реального результата. Остальная схема evidence не проверяется.

N — положительное десятичное число без ведущих нулей. Неверное объявление с известным префиксом, уровнем или размещением → E_STRUCTURE; повтор локального ID → E_DUPLICATE_LOCAL_ID. Простое упоминание R-1 не объявляет элемент. Порядок номеров и непрерывность не проверяются. Отметки вывода R и история переиспользования ID не поддерживаются. Текстовый маркер `TODO(VF)` вне кода → E_DRAFT_PLACEHOLDER. Другие пользовательские TODO не являются автоматически нарушением.

### R-6: Логические ссылки и полный проход

Охват — все обычные `.md` рекурсивно в четырёх фиксированных подкаталогах documents_root, включая неизменённые документы. Отсутствующие подкаталоги допустимы. `.git`, .viaferrata, node_modules, templates, tests и прочая документация вне этих подкаталогов не индексируются. Markdown непосредственно в documents_root также не индексируется. Инкрементального режима и фильтра только текущего change нет.

Адрес — существующий комплект `change-NNNNNN`, документ из R-4 либо документ с допустимым для типа локальным суффиксом AC/R/S/DOD/W/P/V. Комплект существует при наличии полного набора Intent/Spec/Plan. В YAML проверяются значения origin/research/adr/supersedes; scope не является ссылкой.

В теле распознаются самостоятельные `[адрес]` в обычном Markdown-тексте, включая списки Covers/Changes/Depends on/Verifies. Для распознавания учитывается исходный текст и Markdown AST: экранированные скобки, inline/fenced/indented code, HTML, blockquote, Markdown-ссылки/изображения и reference definitions не создают логических ссылок. Неправильно записанный адрес в квадратных скобках с префиксом change-/srs-/research-/adr- → E_REFERENCE_SYNTAX; обычный `[текст]` не имеет машинного смысла. Буквальные упоминания без скобок не проверяются.

Неизвестный адресат → E_REFERENCE_TARGET с местом исходной ссылки и адресом; локальный суффикс не соответствует типу документа → E_REFERENCE_SYNTAX. Удаление цели обнаруживается и для неизменённого источника. Матрица допустимых отношений приведена в [локальном руководстве](../../../templates/README.md), но этим срезом проверяются лишь синтаксис и существование адресатов: семантика Covers/Changes/Verifies, самоссылки, циклы и покрытие ещё не подтверждаются автоматикой. Агент соблюдает принятую матрицу; отсутствие её автоматического контроля видно в отчёте.

### R-7: Диагностика и честный результат

Validate не меняет файлы, даты, mtime, статусы, конфигурацию и не пишет кеш/логи в проект. Диагностики имеют вид `relative/path:line:column CODE: причина; способ исправления`; при ошибке уровня проекта допустима позиция 1:1 конфигурации, при невозможности чтения — путь и системная причина. Дубликаты показывают оба места. Ожидаемые ошибки не печатают необработанный stack trace. Порядок диагностик стабилен: путь, строка, столбец, код.

Коды завершения: 0 — выполнена команда либо нет ошибок заявленных структурных проверок; 1 — ошибки документов; 2 — usage/runtime/config/IO/conflict/unsupported, не позволившие выполнить команду. При смешанных ошибках приоритет у 2. E_UNSUPPORTED всегда означает незавершённый охват, а не пройденную проверку. Предупреждение неизвестного поля документа само по себе не меняет код 0.

Отчёт validate всегда указывает корень, профиль, число прочитанных документов, ошибки/предупреждения и перечень обеспеченных проверок. Даже при коде 0 сообщает: «Базовая структура проверена. Не проверены: смысл и матрица отношений, покрытие, scope/protected_paths по diff, согласование, evidence и завершение. Полная поддержка lite/strict отсутствует». При незавершённом проходе вместо утверждения об успехе — явное сообщение о неполном охвате. Нулевое число документов обозначается отдельно; оно не доказывает готовность проекта. Approved/completed допускаются как значения поля, но не трактуются как подтверждённые события. Команда не меняет профиль и не выполняет shell-команды из документов.

### R-8: Ресурсы и независимое подтверждение

Исходные templates/intent.md, spec.md, plan.md, journal.md, srs.md, research.md, adr.md, руководство templates/README.md и instructions/workflow.md принадлежат пакету. Три генерируемых шаблона содержат полноценные формы, включая необязательные поля и разделы. YAML-примеры необязательных полей закомментированы через `# optional:`/`#`; Markdown-блоки отмечены стандартными комментариями `<!-- optional: … -->`. New сохраняет эти комментарии и блоки. Агент заполняет применимые части и удаляет неприменимые; optional не отключает проверку следующего активного содержимого и не отменяет обязательства strict. Руководство поясняет формы и отношения. В формах, заполняемых командой `new`, используются только параметры `{{change_id}}`, `{{date}}`, `{{title}}`; они подставляются явно без исполнения кода. Готовые документы не перегенерируются при обновлении пакета. Пути ресурсов вычисляются относительно модуля пакета. New использует только Intent/Spec/Plan. Четыре дополнительные формы заполняет агент: Journal с началом Implement, остальные по содержательной необходимости. В них нет заранее утверждённых решений и результатов проверок.

Пакет явно включает bin, src (со схемами), templates, instructions, README, LICENSE и package.json. Tests, документы из documents_root, проектная конфигурация и временные файлы не поставляются. Точные runtime-зависимости фиксируются lockfile; npm test запускает независимые проверки через node:test. Упаковка и локальная установка проверяются без зависимости от исходного каталога, но init и реальный второй проект ещё не входят в этот smoke-test.

Research содержит обязательные Research Question, Context and Scope, Method and Sources, Findings, Conclusion и условные разделы с optional-подсказками. ADR содержит Context and Problem Statement, Decision Outcome с H3 Consequences и Confirmation; Considered Options заполняется при рассмотренных альтернативах. Decision Drivers, Pros and Cons of the Options и More Information составляют optional-расширения MADR в том же файле; их удаление даёт краткую форму. Параметр самостоятельных документов — `{{document_id}}`. Обязательность структуры для исполнителя не означает её проверки в CLI.

Статические фикстуры создаются независимо от templates/new; ожидаемые ошибки заданы до реализации. Генератор проверяется также прямыми ожиданиями содержимого. Сбой записи проверяется управляемым отказом файловой операции, а не предположением о правах пользователя. При проверках new/validate тесты запускают реальный subprocess и сравнивают файлы. Свой change проходит validate дополнительно к независимым тестам.

### R-9: Локальные источники правил

Workflow содержит общие инструкции агенту; локальный AGENTS задаёт особенности проекта. Формы семи типов находятся в отдельных файлах templates, руководство содержит назначение, правила заполнения и матрицу отношений без копирования форм. README описывает использование пакета. Локальные ссылки разрешаются внутри соответствующей поставки.

`docs/GLOSSARY.md` фиксирует значения терминов по действующим локальным источникам без добавления новых правил процесса и возможностей CLI. Ссылка на справочник находится в локальном AGENTS.md; README поясняет назначение docs и исключение из пакета. Поставляемые руководства сохраняют необходимые определения и не зависят от отсутствующего в пакете глоссария.

Комплект описывает действующий контракт и состояние работы. Journal содержит краткое основание согласования, текущую точку работы, актуальные результаты проверок и ограничения без хронологии правок и копий Intent/Spec/Plan. Если принятая редакция сохранена в Git, указывается существующая ревизия; иначе обозначается предел её восстановления. Результат проверки относится только к указанным входам.

### R-10: Пустой комплект и пробельный корень

Непосредственный обычный каталог changes/change-NNNNNN, где номер 000001–999999, обозначает начатый комплект. Validate выдаёт E_STRUCTURE, exit 1, если в нём нет распознанных обязательных Intent/Spec/Plan; для пустого каталога диагностика указывает каталог, позицию 1:1. Отсутствующие документные подкаталоги допустимы; неверные документы получают собственные диагностики. Полный комплект определяется правилами ID и размещения из R-4. New учитывает занятый номер и не требует содержательной готовности существующих комплектов для выбора следующего ID.

Documents_root, для которого trim() возвращает пустую строку, даёт E_CONFIG, exit 2, до записи. Непустые пути с пробелами сохраняются дословно, автоматического trim/переименования нет.

### R-11: Установка без скрытой подготовки кеша

Тест tarball устанавливает пакет обычным npm install с отдельным новым npm-cache и доступом к registry; lifecycle scripts отключены. Пустота кеша перед установкой подтверждается. Недоступность сети или иной сбой означает провал проверки. Тест сохраняет проверку состава, переименование временного источника упаковки и запуск установленного CLI из постороннего cwd. Все временные каталоги удаляются после теста. README сообщает о сетевом этапе.

### R-12: Результаты и необязательная диагностика входов

Journal сохраняет фактические команды, среду, проверенную версию или описание входов, результаты и ограничения. Временные логи, кеши и диагностические манифесты хранятся в игнорируемой .viaferrata/. Постоянный корневой каталог evidence и пофайловый манифест каждой задачи не требуются. Если для конкретной передачи нужны точные входы, их сохранение определяется отдельно.

Необязательный scripts/input-manifest.js без записи в проект выводит JSON с относительными путями, SHA-256 точных байтов и агрегатом строк path + NUL + file_sha256 + LF, отсортированных лексикографически без localeCompare. Входы: bin, src, templates, instructions, tests, scripts, package.json, package-lock.json, viaferrata.toml, README.md, LICENSE. Служебные документы change и временные результаты исключены. Форматирование меняет отпечаток; хеш не доказывает запуск тестов или согласование и не восстанавливает исходники.

## Definition of Done

Выполнены AC-1–11 Intent и обязательные проверки Plan. В Journal сохранены основание согласования, проверенная версия или описание входов, результаты и ограничения; временные логи не являются единственным подтверждением. Исполнитель сверил смысл результата и scope с полным фактическим diff, включая untracked, и сохранил чужую работу. Недоступная обязательная проверка не считается успешной. Completed относится только к этому контракту и не подтверждает полноту профилей, второй проект, commit или release.
