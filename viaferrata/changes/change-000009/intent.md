# Миграция дельт требований на YAML в Markdown

## Goal

Автор записывает дельту требования в одном явно помеченном YAML-блоке задачной Spec. CLI извлекает операцию, адрес и нормативный текст и указывает место нарушения формы.

## Constraints

Переход однократный и несовместимый. Он охватывает поставляемую форму, проверки и существующие дельты этого репозитория. Для внешних проектов достаточно инструкции по переходу. Общая команда миграции и версия формата документов выходят за границы задачи.

## Context

В эксперименте Markdown и YAML одинаково точно передали нормативные тексты. Для каждого формата агент выполнил шесть из шести правок. В прототипе YAML указал место повтора ключа и неверного адреса.

## Acceptance Criteria

### AC-1: Автор записывает и исправляет дельту

- Verification: создать Spec штатным способом, заполнить по примеру, проверить рабочие add, modify и remove. Повторить ключ, пропустить after и повредить адрес. Сверить место, причину и публичный ID сообщения.

### AC-2: Миграция сохраняет требования и ссылки

- Verification: сравнить все шесть архивных дельт до и после конверсии. В отдельных проектах проверить будущий адрес add, потерянную текущую ссылку, исторический remove и предупреждение о незавершённой синхронизации.
