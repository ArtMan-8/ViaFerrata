# Миграция дельт требований на YAML в Markdown

## Change Boundaries

Новая форма применяется к дельтам в Requirements задачной Spec. Мигрируются все шесть операций архивного change-000006 (одна modify и пять add). Сохраняются принятые обязательства, локальные ID, действующие правила адресации, профиль контроля и формат блоков Journal.

## Requirements

### R-1: Форма и расположение

CLI читает одну дельту из самостоятельного блока `yaml` под H3 требования в Requirements по [грамматике дельты](../../../templates/README.md#дельта-требований). Перед блоком допустим обычный текст. У требования без дельты блок отсутствует.

### R-2: Диагностика и границы действия

Повтор ключа, неизвестное поле, неверная операция, состав полей, тип значения, незакрытый или второй блок дельты требуют сообщения о конкретном нарушении. Для ошибки формы рабочей Spec сохраняются правило `requirement-delta` и код `W_FORM`. Для существующего поля указывается позиция нарушения в документе, для отсутствующего — требование или блок и имя поля. Старая активная форма в рабочей Spec получает подсказку о переходе. CLI не извлекает из неё дельту. Действующие ограничения на предупреждения о форме архива сохраняются.

### R-3: Адреса и потребители дельт

CLI проверяет синтаксис и адресата changes по действующим правилам ссылок. Только полностью корректная add допускает отсутствующую будущую цель. При повреждённой дельте ссылка с доступным однозначным адресом по-прежнему проходит обычную проверку. Дельты участвуют в проверке исторической ссылки на снятое требование и в предупреждении о завершённом рабочем change, ожидающем синхронизации.

CLI проверяет содержательные Markdown-ссылки внутри `before` и `after` по действующим правилам, учитывая экранирование и пропуская примеры кода. Такие ссылки не получают разрешения на будущую цель.

### R-4: Однократная конверсия и документация

Шесть архивных операций сохраняют ID, операцию, адрес и значения редакций посимвольно, включая значимые пробелы и переводы строк. Остальной текст Spec, в том числе таблица под R-5, сохраняется. Поставляемые шаблон и инструкции объясняют запись дельты и пример, каталог встроенных правил описывает актуальную форму. Руководство указывает несовместимость и способ проверки существующих рабочих и архивных Spec внешнего проекта.

## Definition of Done

Доказаны равенство шести наборов полей и применение правил ссылок через validate. В документах и тестовых входах старая запись остаётся только там, где явно показана прежняя форма. Исторические описания событий сохраняют исходный смысл.
