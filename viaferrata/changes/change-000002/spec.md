# Контракт подключения проекта

## Change Boundaries

Добавляется init и доступ к расположению общих инструкций через существующий help. Входят тесты сохранности, конфликтов и установленного tarball; README и навигация агента описывают это поведение. Четыре собственных артефакта change включены в scope автоматически, Journal создаётся только с началом Implement. `tests/**` означает файлы на любой глубине для тестов и независимых фикстур этой задачи.

Scope реализации действует после принятия комплекта. Завершённый change-000001, общая модель процесса, зависимости, формат ID и грамматика документов не меняются. Конфигурация и .gitignore самого репозитория не нуждаются в изменении: поведение init проверяется на временных проектах. Общие инструкции уточняются только в части подключения и доступа к ресурсам.

Не входят update, миграции, копирование общих правил в проект, автоматическое редактирование требований, установка зависимостей проекта, Git init/add/commit, runtime агентов, runner/evidence, hooks, публикация, выпуск и второй реальный проект. Версия локального пакета остаётся 0.1.0; проверяемая сборка различается по фактическим входам, а не по одному номеру версии.

## Requirements

### R-1: Интерфейс и выбор проекта

Новая форма команды:

```text
vf [--root PATH] init [--profile lite|strict]
```

--root допускается только перед командой, --profile — только после init, каждый не более одного раза. Позиционных аргументов, --force, --yes, --documents-root и интерактивных вопросов нет. Лишние аргументы, неверный профиль или повторные флаги дают E_USAGE, exit 2. Help описывает этот синтаксис и сохраняет остальные команды.

Корень — cwd либо путь --root относительно cwd; родительские каталоги и Git-root не ищутся. Корень должен быть существующим обычным каталогом. Его отсутствие или неверный тип дают E_CONFIG, exit 2. Исходная директория пакета не является целевым проектом по умолчанию. Git для init не требуется. Пилот сохраняет Node.js 24.x и Linux; неподдерживаемый работающий Node даёт E_RUNTIME, exit 2. Если Node вообще не установлен, сообщение формирует среда запуска; CLI не обещает собственного кода до запуска процесса. README указывает необходимый runtime.

### R-2: Конфигурация и минимальный состав

Если viaferrata.toml отсутствует, --profile обязателен. Без него E_CONFIG с подсказкой явного выбора; рекомендуемый пример — `init --profile lite`. Создаваемый UTF-8 файл содержит только `profile = "lite"` либо `profile = "strict"` и LF. Никакого нового поля версии нет.

Если конфигурация существует, используется действующая схема первого CLI: обязательный profile; documents_root по умолчанию viaferrata; только известные ключи и типы. Файл сохраняется побайтно, включая комментарии. --profile можно опустить; если задан, он должен совпасть с конфигурацией, иначе E_CONFIG до записи. Непустые required_checks/protected_paths дают E_UNSUPPORTED; init не снимает ограничения и не объявляет их проверенными.

Существующий documents_root принимается по действующей схеме и используется последующим new/validate. Нестандартный путь агент задаёт в конфигурации до init; отдельный флаг и перенос файлов не нужны. Пересечение общего корня документов или его предка с viaferrata.toml, AGENTS.md или .gitignore, а также обычный файл на месте документного каталога дают E_CONFIG до записи. Это проверка совместимости мест подключения; она не изменяет правила остальных команд.

Init создаёт или дополняет только viaferrata.toml, AGENTS.md и .gitignore в выбранном корне. README и существующие документы не трогает; changes/specs/research/adr, SRS, Research, ADR, Journal и сам постоянный каталог .viaferrata не создаёт. Каталоги документов возникают при необходимости в других действиях. Init не валидирует содержание существующих документов и не изменяет их даты или статусы.

### R-3: Навигация и инструкции пакета

Пакет остаётся единственным владельцем instructions/workflow.md, templates/README.md и семи форм. Help без конфигурации и успешный init выводят абсолютные пути первых двух ресурсов, вычисленные относительно запускаемого установленного пакета. Help/version не создают файлов. Init до записи проверяет доступность этих ресурсов; отсутствие или ошибка чтения даёт E_IO. Ссылки руководств разрешаются внутри поставки.

В AGENTS.md добавляется один блок между отдельными строками `<!-- viaferrata:begin -->` и `<!-- viaferrata:end -->`. Его содержание задаёт короткий порядок: прочитать локальные правила проекта; запустить используемый vf с --help и открыть названные инструкции и руководство форм; прочитать viaferrata.toml; найти текущий комплект в `<documents_root>/changes/`, где documents_root по умолчанию viaferrata; до Implement согласовать Intent/Spec/Plan, затем вести Journal. Блок напоминает, что validate подтверждает лишь заявленную структуру. Он не утверждает приоритет общих правил над локальными решениями человека.

Блок не содержит абсолютных путей установки, копии общих инструкций, фиксированного change-ID или автоматически выбранной текущей задачи. Если vf отсутствует в PATH, агент использует путь к тому же установленному bin; README содержит пример такого запуска.

Если AGENTS отсутствует, создаётся файл с блоком. Если маркеров нет, блок добавляется в конец с необходимым разделителем строк; исходные байты остаются неизменным префиксом. Если ровно одна полная пара содержит ожидаемый текст текущей реализации, файл не записывается. Сравнение блока допускает LF/CRLF; ручной текст до и после него не сравнивается с шаблоном и не меняется. Неполная, повторная, переставленная пара или изменённое тело — E_EXISTS до любой записи. Диагностика предлагает агенту проверить различие и перенести проектные дополнения за границы блока либо согласовать его восстановление. Автоматического перезаписывания нет. Будущая несовместимая редакция блока также требует явного решения, а не скрытого update.

### R-4: Исключение временного каталога из Git

Если .gitignore отсутствует, создаётся `/.viaferrata/` с LF. В существующем файле сохраняются все исходные байты. Если самостоятельной строки `/.viaferrata/` или `.viaferrata/` нет, в конец добавляется `/.viaferrata/` с необходимым переводом строки. Команда не добавляет игнорирование documents_root или других пользовательских путей.

Если такая строка уже есть и после последнего её вхождения нет правил с первым символом `!`, файл не меняется. Если отрицание есть, возвращается E_EXISTS до записи: нужно проверить порядок правил и вручную оставить исключение временного каталога после отрицаний. Даже отрицание другого пути считается неоднозначностью этого минимального алгоритма; полного интерпретатора gitignore нет. Пустые строки и комментарии не являются отрицаниями. Существующие дубликаты не удаляются; init новых не добавляет. Для распознавания строк учитываются LF/CRLF и начальный UTF-8 BOM.

Добавляемые строки используют имеющийся стиль перевода строк; при его отсутствии — LF. Init не меняет Git index и не снимает уже tracked файлы с учёта. Вывод поясняет, что правило исключает неотслеживаемую .viaferrata/, а ранее tracked данные требуют отдельного решения. Эффект правила проверяется реальным Git в тестах; сам init Git не запускает.

### R-5: Сохранность, конфликты и частичный сбой

До первой записи проверяются все три целевых файла, конфигурация, необходимые каталоги и ресурсы пакета, состояние блока AGENTS и правила .gitignore. Симлинки на пути корня, конфигурации, файлов подключения или документных каталогов отклоняются как E_UNSUPPORTED; обход по ним не выполняется. Необычный тип целевого файла, например каталог вместо AGENTS.md, даёт E_EXISTS. Нечитаемый файл — E_IO. Неподдерживаемая кодировка дополняемого AGENTS/.gitignore (не UTF-8) даёт E_UNSUPPORTED. BOM, LF/CRLF и отсутствие финального перевода строки поддерживаются.

Отсутствующие файлы создаются без перезаписи. Существующая конфигурация никогда не записывается. Добавления в AGENTS/.gitignore не должны обрезать или частично перезаписать прежнее содержимое при управляемой ошибке IO; подготовка полной новой версии и её установка выполняются отдельно. Непосредственно перед записью проверяется, что прочитанный файл не изменился; обнаруженное изменение даёт E_EXISTS. Конкурентные злонамеренные подмены и транзакционность при сбое питания не поддерживаются.

Порядок применения: .gitignore, AGENTS.md, затем новая конфигурация. Нужные добавления выполняются один раз, уже готовые части сохраняются. При отказе E_IO перечисляются завершённые изменения, проблемный путь и способ продолжения. Выполненные добавления не удаляются автоматически; временные файлы самой операции очищаются при обработанном исходе. Команда не утверждает, что откатила весь запуск. После исправления причины повтор дополняет недостающие части; повреждённый файл или изменённый блок по-прежнему требует явного разрешения конфликта. Повтор с неизменными входами не меняет байты, состав и mtime.

### R-6: Результат и диагностика

Успех init — exit 0, включая повтор без изменений. Stdout показывает абсолютный корень, профиль, корень документов, созданные/дополненные/сохранённые файлы, пути инструкций и следующий шаг new → заполнение агентом → validate. Сообщение явно отделяет готовность подключения от полноты профиля, согласования и завершения задачи.

Ошибки выводятся в stderr по принятой форме `relative/path:line:column CODE: причина; способ исправления`, позиция 1:1 допустима для ошибки файла. Для ошибок аргументов допустим путь vf. Ожидаемая ошибка не выдаёт необработанного stack trace. Все ошибки init дают exit 2: E_USAGE, E_RUNTIME, E_CONFIG, E_EXISTS, E_UNSUPPORTED или E_IO. Exit 1 остаётся кодом ошибок документов validate. При частичном сбое нет общего сообщения об успешном подключении.

README описывает первый и повторный запуск, существующую конфигурацию, нестандартный documents_root, владение блоком AGENTS, ограничение gitignore и восстановление после частичного сбоя. Общие инструкции указывают способ найти ресурсы пакета, не меняя модель согласования.

### R-7: Поставка и сохранение существующих команд

Help/version/new/validate сохраняют прежний контракт, кроме добавления init и путей ресурсов в help. New по-прежнему создаёт только три draft-документа, а validate не пишет в проект. Сразу после new незаполненные активные маркеры дают E_DRAFT_PLACEHOLDER и exit 1; успешный validate проверяется на заранее заполненном независимом примере, не полученном из шаблонов генератора.

Локальный npm tarball включает необходимые исполняемые файлы, зависимости, схемы, формы и инструкции; пользовательские документы, конфигурация проекта, тестовые данные и временные логи исключены. Проверка поставки использует новый пустой npm-cache, обычную установку с отключёнными lifecycle scripts, временную копию источника упаковки, которая затем становится недоступной. Из постороннего cwd установленный bin выполняет help/version → init → повтор init → new → validate с обоими ожидаемыми исходами. Проверяется чтение инструкций и сохранность ручного текста. Никакой ресурс не берётся из исходной директории пакета.

Все тестовые проекты и установки изолированы в системном временном каталоге и удаляются после соответствующих тестов, в том числе при ошибке. Недоступная сеть или иной сбой обязательной установки не считается passed. Реальный второй проект остаётся отдельным испытанием вехи 1.

## Definition of Done

AC-1–8 выполнены и подтверждены применимыми проверками Plan. Обязательны npm ci, npm run typecheck, npm test, npm run build, node bin/vf.ts --root . validate, git diff --check и сверка tracked/untracked со scope. Форматирование завершено до итоговых проверок; после изменения входов повторяются затронутые проверки. В Journal, созданном при Implement, сохранены фактическое основание принятия комплекта, входы, команды, среда, результаты и ограничения. Чужие данные и завершённый change-000001 сохранены. Completed не означает публикации, принятия продукта человеком или завершения всей вехи 1.
