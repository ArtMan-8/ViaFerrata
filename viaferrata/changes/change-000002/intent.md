# Подключение проекта командой init

## Goal

Подготовить существующий каталог проекта к работе с ViaFerrata одной командой: создать необходимую конфигурацию, дать агенту доступ к правилам установленного пакета и исключить временные данные из Git. Существующее содержимое проекта должно сохраниться; пользователь не переносит служебные поля вручную.

## Constraints

Intent/Spec/Plan приняты; реализация выполняется в их границах. Journal ведётся с началом Implement. Завершённый change-000001 не переоткрывается.

Сохраняются TypeScript ESM, Node.js 24.x, npm и Linux. Нового runtime агентов, update, миграций, runner/evidence, контроля завершения, публикации и настройки второго реального проекта в задаче нет. Init не обещает полной поддержки lite/strict. Работы выполняются в текущем репозитории, испытания — в изолированных временных каталогах.

## Context

CLI предоставляет help/version, new и базовый validate. Исходники CLI, тесты и скрипты запускаются напрямую как TypeScript в Node.js 24; npm-пакет поставляет собранный JavaScript. Подключение проекта пока требует ручной подготовки конфигурации и навигации. Init должен устранить эту работу, сохранив существующие команды и данные проекта.

В репозитории используется профиль lite; documents_root по умолчанию — viaferrata. Внутри него фиксированы changes/, specs/, research/ и adr/. Общие правила, схемы и формы принадлежат пакету; конфигурация и заполненные документы — проекту. Правила доступны в instructions/workflow.md, формы и матрица отношений — в templates/README.md.

Проверка поставки должна охватить init вместе с существующими командами и чтением инструкций из установленного пакета. Испытание второго реального проекта остаётся отдельной задачей.

## Acceptance Criteria

### AC-1: Первый запуск подготавливает только выбранный проект

В пустом существующем каталоге `init --profile lite` создаёт viaferrata.toml, AGENTS.md и .gitignore по контракту. README, комплекты документов, пустые документные подкаталоги и постоянный временный каталог не создаются. Cwd либо явный --root однозначно определяет место записи; соседний проект не меняется.

- Covers:
  - [change-000002/spec/R-1]
  - [change-000002/spec/R-2]
- Verification: subprocess из cwd проекта, вложенного и постороннего cwd; абсолютный и относительный --root, путь с пробелами, проект без Git. Сверить состав и байты целевого, соседнего и исходного каталогов; без --root родитель не выбирается.

### AC-2: Конфигурация проекта сохраняет смысл и байты

Существующие lite/strict, documents_root, комментарии и форматирование сохраняются. Новый профиль выбирается явно; несовпадающий флаг, недопустимый TOML, неизвестный ключ и неподдерживаемые ограничения останавливают init до записи. Init не переключает профиль и не переносит документы.

- Covers:
  - [change-000002/spec/R-2]
- Verification: существующий strict, нестандартный documents_root с пробелами, комментарии и пустые массивы; отрицательные случаи из R-2. Сравнить конфигурацию и документы побайтно и по mtime; затем new должен использовать сохранённый documents_root.

### AC-3: Агент находит правила установленного пакета

Краткий блок AGENTS направляет к viaferrata.toml, комплектам проекта и инструкциям пакета. Help и успешный init показывают доступные пути instructions/workflow.md и templates/README.md именно запускаемой установки. Проект не содержит абсолютных путей машины или копии общих правил.

- Covers:
  - [change-000002/spec/R-3]
- Verification: прочитать оба ресурса и проверить их локальные ссылки после установки tarball при недоступном источнике упаковки; сменить место установки, повторить init и сравнить AGENTS. Help/version проверить без конфигурации.

### AC-4: Повтор и ручные правки не теряются

Второй init без изменений возвращает 0 без изменения состава, байтов и mtime. Правки вне блока AGENTS сохраняются. Изменённый, неполный или повторный блок даёт E_EXISTS до записи и остаётся нетронутым. Существующие README, документы и конфигурация не переписываются.

- Covers:
  - [change-000002/spec/R-3]
  - [change-000002/spec/R-5]
- Verification: сравнить снимки до/после первого дополнения и повторов; включить CRLF, BOM, отсутствие последнего перевода строки, ручной текст с обеих сторон блока и каждый конфликт маркеров. Проверить восстановление недостающего файла после частичного подключения.

### AC-5: Временные данные исключены без потери правил Git

Init добавляет только необходимое правило для корневой .viaferrata/ либо сохраняет уже подходящее правило. Повтор не дублирует его. Неоднозначность с последующим отрицанием диагностируется без записи. Пользовательские правила и Git index сохраняются; documents_root не исключается командой.

- Covers:
  - [change-000002/spec/R-4]
- Verification: файлы с существующим правилом, без него, с отрицаниями до/после, CRLF и без финального LF; сравнить исходные байты. В временном Git-репозитории использовать git check-ignore для .viaferrata/cache и обычного документа; сравнить index, в том числе при уже tracked временном файле.

### AC-6: Конфликты и сбои дают безопасный частичный результат

Выявляемые заранее ошибки не оставляют изменений. При ошибке IO после первой записи уже выполненные добавления названы, существующие файлы не усечены, автоматического удаления нет. Повтор дополняет отсутствующие части либо точно сообщает оставшийся конфликт; успех не заявляется до завершения всех действий.

- Covers:
  - [change-000002/spec/R-5]
  - [change-000002/spec/R-6]
- Verification: файл вместо каталога, симлинки, пересечение documents_root с файлами init, недоступный ресурс пакета; управляемый отказ записи на каждом шаге, включая добавление в существующий файл, затем повтор. Проверить stderr, код 2, перечень фактических изменений и сохранность обоих проектов.

### AC-7: Установленный tarball выполняет полный сценарий

После установки help/version → init → new → validate работают из постороннего cwd без доступа к источнику упаковки. Незавершённый new даёт E_DRAFT_PLACEHOLDER и exit 1; заполненный независимый пример даёт exit 0. Повторные init/validate сохраняют проектные файлы.

- Covers:
  - [change-000002/spec/R-7]
- Verification: tests/package.test.ts с новым пустым npm-cache, временной копией источника и установленным bin. Проверить состав пакета, доступность инструкций, оба результата validate и очистку /tmp/vf-test-\* этого теста. Сбой сети означает непройденную проверку.

### AC-8: Регрессия и границы результата проверены

Прежние команды и независимые фикстуры проходят обязательные проверки; собственные документы структурно корректны. Документация объясняет init, конфликты, восстановление и ограничения. Завершение относится только к этому контракту, а не ко всей вехе 1.

- Covers:

  - [change-000002/spec/R-7]
- Verification: npm ci, npm run typecheck, npm test, npm run build, node bin/vf.ts --root . validate, git diff --check и сверка tracked/untracked со scope; после реализации сохранить в Journal команды, среду, входы, фактические результаты и ограничения.
