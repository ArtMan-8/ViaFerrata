# Сводка результатов проверки в CLI

## Goal

Пользователь за один вызов CLI видит исход каждой проверки, источник результата, проверенную редакцию и основание согласования работы.

## Constraints

CLI только читает данные и выводит сводку. Поддержка старых записей Journal и их миграция в задачу не входят. Собственный runner, автоматическая оценка актуальности evidence, контроль scope и допуск к completed остаются за границами изменения.

## Context

В deep источником сводки служит Journal. При возобновлении агент сверяет его с текущим Plan и рабочим деревом даже после утраты временных заметок. В vibe источником служит отчёт агента или CI.

## Acceptance Criteria

### AC-1: Передача deep-задачи

После утраты временных файлов пользователь видит записанный результат и пределы его подтверждения.

- Covers:
  - [change-000008/spec/R-1]
  - [change-000008/spec/R-3]
- Verification: получить сводку по Journal с двумя успешными проверками разных критериев на разных редакциях и отдельно записанным решением пользователя, сверить вывод с исходными данными и проверить сохранность файла.

### AC-2: Отчёт CI в vibe

Пользователь видит исход и проверенную редакцию из отчёта CI. При отсутствии сведений о согласовании это явно указано.

- Covers:
  - [change-000008/spec/R-2]
  - [change-000008/spec/R-3]
- Verification: передать отчёт с несколькими проверками через стандартный ввод без change ID в проекте без Journal. Сверить каждую запись с выводом одного вызова и проверить отсутствие созданных файлов.
