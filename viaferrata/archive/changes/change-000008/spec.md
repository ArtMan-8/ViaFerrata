# Сводка результатов проверки в CLI

## Change Boundaries

Один вызов выводит человекочитаемую сводку по выбранному Journal или переданному отчёту. Агент ведёт Journal. Команда только читает данные. Действующие Markdown-адреса V и связи Verifies сохраняют своё назначение. Записи сводки не требуют собственных ID. Проверки validate и действующая SRS встроенных правил сохраняются.

## Requirements

### R-1: Сводка по Journal

Команда `vf summary change-NNNNNN` ищет указанный ID в рабочем каталоге и архиве. Для архивного комплекта выводит пометку «архив». Если ID найден в обоих местах, сообщает о конфликте без вывода сводки. Вызов без аргументов подсказывает обе формы команды.

Агент ведёт в Markdown-Journal по одному блоку кода с меткой `yaml` для каждого списка: `checks` в Verification и `decisions`, если он есть, в Significant Events. Шаблон содержит `checks: []`; агент добавляет записи после прогона. Два блока с одним списком в его разделе дают ошибку неоднозначности. При отсутствии блока `checks` CLI сообщает о неподдерживаемом формате и возвращает ненулевой код. Старые Journal сохраняются без миграции.

Сводка доступна без временных файлов. Точку продолжения, команду проверки, среду и ограничения агент может записать обычным текстом. CLI извлекает только списки из указанных разделов и сохраняет все байты Journal.

### R-2: Сводка по переданному результату

В vibe `vf summary --stdin` читает один отчёт YAML или JSON без Markdown-обёртки и change ID. Файл можно передать через перенаправление stdin. Схема записей совпадает со схемой Journal. Эквивалентные входы дают одинаковую сводку. Команда не создаёт файлов.

### R-3: Схема отчёта и вывод

Обязательное поле `checks` содержит список записей. Для каждой записи CLI выводит четыре поля:

- `subject` — что проверяли;
- `outcome` — сообщённый исход, например `passed` или `failed`;
- `source` — откуда известен результат, например «отчёт CI, запуск 42»;
- `revision` — строка с описанием проверенных входов или `null`. CLI сохраняет описание целиком. При `null` выводит «проверенная редакция неизвестна».

Первые три поля содержат непустой текст. Необязательное поле `executor` называет исполнителя. При его отсутствии или значении `null` исполнитель неизвестен. CLI выводит проверки в порядке записи, включая проверки с одинаковым исходом.

Необязательный список `decisions` содержит строки. Каждая строка описывает принятое решение, его основание и область действия по правилам Journal. CLI выводит решения один раз. При отсутствии решений он сообщает, что основание согласования не указано. Проверенная редакция сама по себе не подтверждает принятие пользователем или актуальность результата.

### R-4: Полнота сводки и код завершения

CLI сначала читает и проверяет весь вход. При ошибке он указывает причину и доступное место ошибки, возвращает ненулевой код и не выводит частичную сводку. К ошибкам относятся пустой stdin, отсутствие обязательного списка или поля, неверный тип и повтор ключа в одной записи.

Если сводка выведена полностью, команда возвращает 0, в том числе при исходе `failed`. При явном `checks: []` она выводит доступные решения и строку «Записанных проверок: 0».

## Definition of Done

Через CLI проверены оба сценария из Intent и граничные случаи из Plan. Для эквивалентных отчётов YAML и JSON получен одинаковый вывод. Проверки проекта охватывают код, документацию и использование команды с шаблоном из установленного пакета.
