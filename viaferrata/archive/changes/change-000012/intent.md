# Допуск deep-задачи к completed

## Goal

Агент завершает согласованную deep-задачу одной командой. При каждом отказе он видит, какое условие осталось выполнить.

## Constraints

Сохранять исходные результаты проверок, профиль проекта и историю завершённых changes. Предупреждения сами по себе не дают агенту полномочий менять документы.

## Context

До этого изменения агент вручную переводил Plan в `completed`. Команда `vf validate` проверяла структуру и отношения, `vf scope` проверяла пути Git, а `vf summary` выводила записанные исходы проверок.

## Acceptance Criteria

### AC-1: Безопасный переход

При успехе поле `execution` в Plan получает значение `completed`. При отказе его содержимое сохраняется. Повторный вызов после успеха сохраняет файлы.

- Covers:
  - [change-000012/spec/R-1]
- Verification: Завершить корректный комплект, сравнить файлы до и после, повторить вызов. По очереди убрать согласование и итог, открыть шаг, изменить путь вне scope и имитировать ошибку записи.

### AC-2: Обязательные проверки

Команда указывает обязательную проверку, для которой отсутствует однозначный успешный результат с источником и известной редакцией.

- Covers:
  - [change-000012/spec/R-2]
- Verification: Убрать результат обязательного `typecheck` при успешных тестах. Проверить случай, когда у всех проверок исход `blocked`, неизвестную редакцию, конфликт исходов и подтверждённый успешный повтор. Повторить оценку после записи итога в Journal.

### AC-3: Проверка каждого AC

При включённом правиле `verification-coverage` каждый AC имеет ссылку из V с известной Revision и подтверждённым исходом passed. В обычном lite пропуск ссылки сам по себе допуска не блокирует.

- Covers:
  - [change-000012/spec/R-3]
- Verification: На двух AC проверить отсутствие ссылки, неизвестную Revision при известной редакции другой проверки и отрицательный исход при успешной сборке. Сравнить strict, lite и lite с включённым правилом.

### AC-4: Сохранение согласованной политики

Команда обнаруживает расхождение перечня проверок с согласованным и ослабление исходной политики проекта. После принятой дельты применяет обновлённый перечень.

- Covers:
  - [change-000012/spec/R-4]
- Verification: Удалить обязательный `subject` только из Spec, затем воспроизвести принятую дельту scope с изменением применимых проверок. Попробовать отключить применимое правило в конфигурации.

### AC-5: Действие правил во времени

Ошибка разрешения зависимости текущего change блокирует переход. Новые условия завершения применяются только к целевому комплекту. Исторические документы сохраняются.

- Covers:
  - [change-000012/spec/R-5]
- Verification: Сравнить старый архивный Journal, старый завершённый рабочий Journal и целевой Journal. Нарушить ссылку текущей Spec, отдельно оставить чужой change в работе без итогового отчёта. Проверить сохранность исторических файлов.
