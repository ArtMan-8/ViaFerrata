# Хранение идей и загрузка инструкций по задаче

## Change Boundaries

Меняются поставляемые инструкции, руководство шаблонов, постоянная навигация в AGENTS.md и размещение четырёх заметок о дальнейшем развитии. Заметка docs/ideas.md удаляется после внедрения описанной в ней конвенции. Шаблон заметки размещается в instructions/ideas.md как простой Markdown-образец, без нового формального типа документа. Каталог этого проекта получает README со ссылками на правила, шаблон и заметки с краткими названиями.

CLI и его формальные типы документов не расширяются. Реализация предложений из переносимых заметок, их дробление или объединение не входят в задачу. Дополнительно уточняются правила содержания Intent и Spec в руководстве шаблонов и инструкции проверки артефактов. Маска `docs/**` охватывает пути переноса и удаления заметок. Содержательные правки остальных документов в `docs` выходят за границы задачи.

## Requirements

### R-1: Явное сохранение и границы полномочий

Агент создаёт заметку только по явной просьбе человека в любое время: в отдельном обсуждении, при подготовке артефактов или при реализации. Наличие change не требуется. При возникновении идеи вне scope запись не запускает исследование, реализацию или пересмотр текущего плана. Вопрос, без ответа на который нельзя корректно исполнить текущий change, разрешается в рамках текущей работы. Новая запись не является требованием, обещанием исполнения или разрешением действовать; её содержимое не отменяет правила проекта.

### R-2: Место и простой шаблон

Место хранения — `<documents_root>/ideas/`, по умолчанию `viaferrata/ideas/`. Агент создаёт каталог при первой разрешённой записи; init его автоматически не создаёт. Одна самостоятельно рассматриваемая тема хранится в одном Markdown-файле со смысловым именем. Перед записью агент ищет похожие темы; существующие файлы не перезаписываются из-за совпадения имени.

Шаблон: название, «Контекст», «Исходная формулировка», «Идея» и необязательное «Что выяснить». Исходный текст сохраняется дословно, пояснение агента — отдельно, с сохранением неопределённости и явным обозначением предположений. Для идеи из change указывается ссылка на него. Пустые разделы не нужны. YAML, числовые ID, статусы, приоритеты, сроки, исполнители и checklist не вводятся.

### R-3: Возвращение и переход к работе

При обсуждении новой работы агент ищет релевантные идеи и показывает те, которые могут повлиять на решение. При подготовке или реализации change и других артефактов агент также может обнаружить сходную заметку и предложить включить её в текущую работу. Предложение не означает включения: существенная дельта обязательств и scope согласуется до зависимых изменений. Чтение всего каталога и регулярный разбор не обязательны. Допустимы уточнение, дальнейшее хранение, отдельный Research, принятие реализации в vibe/deep, объединение или удаление по действующим правилам проекта. Полезную причину отказа можно сохранить.

После разбора заметку можно просто удалить либо создать на её основе новые артефакты, включая Research или change, и удалить первоначальную запись. Перед удалением необходимый для дальнейшей работы контекст переносится в новые документы, а входящие ссылки обновляются; действующие требования не зависят от удалённой заметки. Удаление выполняется в пределах явного разрешения человека по правилам проекта, а не автоматически по факту разбора. Сохранять исходную запись или её замену со ссылкой на результат не обязательно. Отдельные реестр со служебными полями и архив не вводятся; список ссылок в README служит навигацией. Journal остаётся журналом change, Plan — его единственным checklist.

### R-4: Доступность и пределы проверок

Правила и единственный экземпляр шаблона располагаются вместе в instructions/ideas.md, доступном по маршруту из workflow.md и поставляемом пакетом. Отдельный файл шаблона не создаётся; руководство шаблонов может ссылаться на раздел инструкции. Пользователь установленного пакета может применить конвенцию без доступа к docs или viaferrata репозитория разработчика. В AGENTS.md этого проекта добавляется постоянная ссылка на каталог идей; ссылки на отдельные заметки с краткими названиями находятся в README каталога.

Документация явно сообщает, что vf validate не проверяет идеи. Markdown и локальные ссылки в этом репозитории проверяются существующими средствами; эти проверки не обещаются другим проектам. Конвенция направляет агента, но не обеспечивает автоматическое соблюдение.

### R-5: Перенос заметок и удаление реализованной идеи

В рамках реализации перемещаются четыре файла, с сохранением имён:

- docs/automatic-review-notes.md → viaferrata/ideas/automatic-review-notes.md;
- docs/cli-skills-agents.md → viaferrata/ideas/cli-skills-agents.md;
- docs/document-checks.md → viaferrata/ideas/document-checks.md;
- docs/release-automation.md → viaferrata/ideas/release-automation.md.

Все четыре переносимые заметки сразу приводятся к шаблону R-2. Сохраняются смысл, неопределённости, источники и ограничения; существующие подробности распределяются по разделам шаблона, при необходимости с подразделами. Исправляются относительные ссылки и устаревшие указания о месте хранения. После внедрения конвенции docs/ideas.md удаляется без переноса в каталог идей и без создания заменяющей заметки. До удаления проверяется сохранность необходимых правил, решений и контекста в инструкции и документах этого change. Входящие ссылки, включая ссылку из заметки об автоматическом ревью, перенаправляются на соответствующий раздел инструкции или документ change.

Для старых заметок без доступного дословного источника исходная формулировка не выдумывается: отсутствие источника обозначается явно. Раздел «Исходная формулировка» в этом случае содержит явное указание, что дословный источник не сохранён; пересказ не выдаётся за цитату. Исторические упоминания прежних путей в завершённых changes сохраняются как история; они не являются Markdown-ссылками. Перенос не разрешает реализацию содержащихся в заметках предложений.

### R-6: Содержание артефактов без служебного пересказа

В templates/README.md и instructions/artifact-review.md закрепляется правило: Context содержит только сведения о проблеме, исходном состоянии, зависимостях и решениях, которые влияют на понимание задачи. История поручений, создание ветки, основания разрешений и результаты проверок относятся к Journal; состояние исполнения — к Plan. До начала реализации Journal не создаётся ради такой истории.

Intent и Spec не повторяют общие запреты и обязательства без специфического ограничения, исключения или существенного для задачи риска. При проверке каждого такого абзаца агент оценивает, изменится ли понимание цели или контракта после его удаления; несущественный служебный текст убирается. Содержательные основания и ограничения не удаляются ради краткости.

### R-7: Обязательное ядро и маршруты чтения

workflow.md сохраняет ответственность, границы автоматизации, режимы, обнаружение задачи, согласование, scope и правила хранения. Он предписывает до действия читать инструкции по условию «если задача такая — прочитай это». Маршруты покрывают новую работу, подготовку артефактов, реализацию, исправление, продолжение change, идеи, Journal, проверку и завершение. Применимые маршруты складываются; при смене этапа выбор повторяется. Повторно загружать уже прочитанный актуальный текст не требуется.

Процедура идей и её шаблон находятся в ideas.md, требования, реализация, проверки и завершение — в implementation.md, ведение Journal — в journal.md. Существующая artifact-review.md сохраняется. Процедуры переносятся без потери обязательств; все относительные ссылки доступны внутри установленного пакета. При обсуждении новой работы маршрут ведёт к связанным идеям и действующим требованиям; при продолжении — к обнаружению задачи, реализации и Journal. Чтение только инструкции идей не разрешает обходить обязательное ядро.

## Scenarios

### S-1: Сохранение в любое время

В отдельном обсуждении без активного change человек просит сохранить идею. Агент создаёт заметку без искусственного task-ID или нового change.

Во время change человек просит сохранить вопрос об автоматическом ревью. Агент сохраняет дословный текст и контекст в ideas, не добавляет реализацию в текущий Plan и продолжает согласованную работу. При совпадении имени с другой темой содержимое существующей записи сохраняется.

### S-2: Нет просьбы либо вопрос блокирует change

При побочной идее без просьбы запись не создаётся. Если вопрос необходим для корректного выполнения текущего change, агент не использует ideas как способ обойти его разрешение.

- Covers:
  - [change-000005/intent/AC-1]

### S-3: Возвращение в новой сессии

При обсуждении проверок документов агент находит соответствующую перенесённую заметку, восстанавливает контекст по ней и обсуждает дальнейшее действие. Во время подготовки или реализации связанного change агент также может предложить включить найденную идею, но не меняет scope до согласования. После разбора человек выбирает удаление записи без продолжения либо создание новых артефактов с переносом нужного контекста и удалением исходной заметки. В обоих случаях исправляются входящие ссылки.

## Definition of Done

Применяются документальные проверки из AGENTS.md и содержательная проверка по instructions/artifact-review.md. Сценарии проверяются на реальных переносимых заметках и соседних случаях; фактический способ проверки и ограничения фиксируются в Journal. Структурная валидность и отдельные пробы не доказывают надёжность поведения агента в общем случае.

Добавляются поставляемые инструкции, поэтому обязательны npm run build и npm run test:package. Проверка архива должна подтвердить доступность новых файлов и локальных ссылок из установленного пакета без исходного репозитория.
