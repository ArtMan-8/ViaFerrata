# Встроенные правила ViaFerrata

## Change Boundaries

Первое расширение core для deep-комплектов проверяет структурное покрытие. Полная матрица отношений, проверка diff по scope и автоматизация завершения остаются отдельными задачами.

## Requirements

### R-1: Выбор профиля и дополнительных правил

- Operation: modify
- Changes:
  - [srs-000001/R-1]
- Before: CLI принимает отсутствие `required_checks` или пустой массив `required_checks = []` в `viaferrata.toml`. Значение должно быть массивом непустых строк; неверный тип или пустая либо состоящая только из пробелов строка дают `E_CONFIG`. Непустой массив даёт `E_UNSUPPORTED`: исполнение обязательных проверок этой настройкой не поддерживается. Ключ `checks`, включая форму `[[checks]]`, даёт `E_CONFIG` как неизвестный ключ. Эти правила действуют при чтении конфигурации командами init, new и validate.

  Отклонение конфигурации не разрешает удалять обязательства ради успешного запуска CLI. Применимые проверки проекта агент выполняет самостоятельно; успешный validate не подтверждает выполнение этих проверок, достоверность evidence или завершение задачи.

- After: CLI принимает required_checks как список ID дополнительных встроенных правил. Отсутствующее поле и пустой список оставляют профиль без дополнений. Базовые проверки конфигурации, структуры, идентичности и ссылок действуют в обоих профилях. Правило plan-requirement-coverage входит в strict и может быть включено в lite. Неизвестный ID или неверный тип даёт E_CONFIG; повторный выбор одного правила оставляет его включённым однократно. Команды init, new и validate используют общую конфигурацию. Поведение protected_paths сохраняется.

### R-2: Покрытие рабочей Spec

- Operation: add
- Changes:
  - [srs-000001/R-2]
- After: При включённом plan-requirement-coverage команда validate проверяет каждый объявленный R рабочей Spec. В том же deep-комплекте у шага P должна быть явная связь Covers на этот R либо на AC Intent, у которого есть Covers на этот R. Отсутствие покрытия даёт E_PLAN_COVERAGE с адресом требования и ненулевой код завершения. Примеры кода, текстовые упоминания и связи другого change покрытия не дают. В архиве правило не применяется. В vibe отсутствие комплекта допустимо. Покрытие описывает план работ; проверку поведения выполняет агент или CI средствами проекта.

## Definition of Done

Проверить штатные команды и установку пакета. Удалить отвергнутые определения внешних команд и снимки. Синхронизировать SRS и архивировать комплект после успешных проверок.
