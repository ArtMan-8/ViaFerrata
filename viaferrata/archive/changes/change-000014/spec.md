# Создание документов по явному типу

## Change Boundaries

Изменяется публичный контракт new. Параметры init и процесс дальнейшего редактирования документов сохраняются. Гарантия полной записи действует в момент публикации командой new. Она не требует заполнять Journal за один раз.

## Requirements

### R-1: Создание черновиков по типу

```yaml
operation: modify
changes: srs-000003/R-4
before: |-
  `vf new "Название задачи"` принимает одно непустое однострочное название. Название используется в заголовках документов с экранированием Markdown. Команда выбирает следующий шестизначный номер после наибольшего занятого в рабочих и архивных комплектах. Она создаёт внутри `documents_root/changes` каталог `change-NNNNNN` и ровно три файла из форм установленного пакета: `intent.md`, `spec.md` и `plan.md`. Статусы `draft`, `execution` плана `not_started`, даты создания и обновления соответствуют текущей дате UTC. В `stdout` выводятся ID, относительный путь и состав черновика. Код успеха 0. Название с префиксом `--` отклоняется с `E_USAGE`. Активные подсказки требуют заполнения перед успешным `validate`.

  Ошибка индекса, препятствующая созданию, возвращает код по категории диагностики (1 для ошибок документов, 2 для незавершённой операции). Исчерпание номеров, конфликт создания и сбой записи дают код 2. Команда сохраняет существующие файлы, сообщает созданные пути при частичном сбое и учитывает занятый номер при следующем запуске.
after: |-
  Команда принимает тип и одно непустое однострочное название: `vf new change "Название"`, `vf new srs "Название"`, `vf new adr "Название"` или `vf new research "Название"`. Название с префиксом `--` запрещено. При ошибке аргументов, в том числе при вызове прежней формы с одним названием, CLI выводит `E_USAGE` и новый синтаксис в `stderr`, возвращает 2 и сохраняет дерево файлов.

  Команда проверяет индекс идентичности рабочих и архивных документов. Для каждого типа отдельно выбирает номер после наибольшего занятого, начиная с 000001. Для самостоятельных документов источник номера — ID в YAML независимо от имени файла. Для change учитываются также непосредственные пути `change-NNNNNN` в рабочем и архивном changes. Если наибольший занятый номер равен 999999, команда возвращает `E_ID_EXHAUSTED`. Блокирующая ошибка индекса даёт код своей категории (1 для ошибок документов, 2 для незавершённой операции). Подсказки прежних черновиков сами по себе созданию не препятствуют.

  Внутри `documents_root` команда создаёт `changes/change-NNNNNN` с `intent.md`, `spec.md` и `plan.md` либо один файл `specs/srs-NNNNNN.md`, `adr/adr-NNNNNN.md` или `research/research-NNNNNN.md`. Она использует актуальные формы установленного пакета, подставляет ID, текущую дату UTC в `created` и `updated` и экранированное для Markdown название. Документы получают `status: draft`, Plan получает `execution: not_started`. При успехе `stdout` содержит ID, относительный путь и состав результата, код завершения 0. Активные подсказки требуют заполнения перед успешным `validate`.

  По конечному пути публикуется только полностью записанный файл или комплект. Сбой записи до публикации даёт `E_IO` и код 2. Занятый конечный путь и конфликт между вызовами, выбравшими один ID, дают проигравшему `E_EXISTS` и код 2 без повторного выбора. Существующие файлы сохраняются. При публикации комплекта внешний процесс может успеть создать пустой каталог по конечному пути между последней проверкой и переименованием. В этом случае каталог может быть заменён. Аварийное прерывание может оставить временные данные вне индексируемых каталогов.
```

### R-2: Руководства и сценарии создания

Help и quickstart показывают вызовы и расположение результата. Инструкции объясняют выбор типа, заполнение и согласование. Агент по умолчанию добавляет к ID самостоятельного документа краткое смысловое имя перед созданием ссылок, сохраняет ID в YAML и сообщает конечный путь. При занятом имени сохраняет исходный файл и сообщает конфликт. Создание Journal остаётся шагом начала реализации. В обеих заметках оставить исходную формулировку, проверенный итог, ссылки и открытые вопросы о skills, поиске задач, агентных интеграциях, версии формата и миграции.

### R-3: Размещение постоянных требований и сохранение истории

Добавить к именам трёх рабочих SRS их ID и дефис, сохранить существующий смысловой суффикс и обновить текущие ссылки. Уточнить введение каталога встроенных правил о проверке идентичности для всех форм new и обзор команд CLI-SRS. Сохранить исторические описания и scope. Перенести завершённые комплекты change-000001 и change-000007 в архив после сверки обязательств. Сохранить ID и содержание всех восьми файлов, исправить относительные ссылки, затронутые перемещением.
