# Валидация и проверки документов

## Контекст

Заметка от 2026-11-14. Действующие проверки перечислены ниже; открытые вопросы касаются автоисправлений, границ контроля и допуска к завершению.

### Текущее состояние

| Команда                   | Что проверяет                                                                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run format:check`    | Оформление файлов средствами Oxfmt.                                                                                                          |
| `npm run lint`            | TypeScript и Markdown; порядок путей scope автоматически не проверяется.                                                                     |
| `npm test`                | Локальные ссылки реальных документов репозитория; шаблоны, генерацию и валидатор на тестовых примерах.                                       |
| `node bin/vf.ts validate` | Рабочие и архивные документы: ID, ссылки и отношения. Проверки формы и покрытия зависят от расположения документа, профиля и состояния Plan. |
| `npm run test:package`    | Установку tarball, доступность поставляемых инструкций и шаблонов, ссылки и пользовательский сценарий установленного CLI.                    |

`npm test` проверяет работу валидатора на фикстурах, но не заменяет отдельный запуск `validate` для текущих change-комплектов. Проверка самого инструмента и проверка документов проекта — разные действия.

`npm run format` переписывает оформление, а `format:check` только проверяет его. Агент упорядочивает scope как дерево проекта по [руководству шаблонов](../../templates/README.md). Команда scope использует тот же порядок для контрольной суммы и проверяет принадлежность изменённых путей. Вопрос автоматической правки оформления остаётся открытым.

Структурные проверки не подтверждают смысл требований, обоснованность origin, человеческое согласование, достоверность результатов или завершение задачи. Эти вопросы рассматриваются при [содержательной проверке артефактов](../../instructions/artifact-review.md).

## Идея

Расширять автоматическую проверку документов по мере выявления конкретных нарушений. Уже реализованные проверки отношений, циклов и покрытия описаны в [каталоге правил](../specs/built-in-checks.md).

## Что выяснить

- Как разделить исправление оформления, проверки текущих документов и тесты самих проверяющих инструментов между format, lint, test и validate?
- Какие правила относятся только к этому репозиторию, а какие должны действовать для пользователей установленного CLI?
- Какой охват нужен для draft-документов, исторических changes, шаблонов, примеров и независимых фикстур?
- Как сообщать ошибки и сохранять файлы при проверке? Какие автоматические исправления допустимы без изменения смысла документов?
- Какие проверки требуют содержательного ревью?

Перед добавлением правила определить ожидаемый результат на допустимом и ошибочном документах.
