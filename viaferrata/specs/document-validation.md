# Проверка документов и области изменений

## Purpose and Boundaries

Пользователь и агент проверяют структуру документов проекта и пути, изменённые при выполнении deep-задачи. Согласование работы, проверка поведения и решение о завершении требуют отдельных оснований.

## System Overview

Команда `vf validate` индексирует рабочие и архивные документы, проверяет структуру, идентичность и ссылки. Состав правил и различия профилей определяет [каталог встроенных проверок](built-in-checks.md). Для проверки путей в lite и strict служит отдельная команда `vf scope change-NNNNNN`. Для проверки нужен рабочий комплект в проекте, корень которого совпадает с корнем рабочего дерева Git. Исходный коммит должен быть доступен и входить в историю HEAD. При конфликте индекса, изменённом симлинке или подмодуле команда завершает проверку с ошибкой. Агент сохраняет решение пользователя, исходную базу и сумму согласованных масок по [правилам Journal](../../instructions/journal.md#согласование-и-решения).

## Requirements

### R-1: Основание проверки

При создании Spec и после каждой дельты агент записывает scope в порядке дерева проекта. CLI использует тот же порядок для вычисления суммы. Перестановка строк сохраняет сумму.
Команда vf scope change-NNNNNN --digest выводит SHA-256 принятого к рассмотрению списка масок рабочей Spec без записи в файлы. Команда vf scope change-NNNNNN проверяет изменения по этой Spec и записи в Journal. В Significant Events агент хранит YAML-блок scope_check с полями base (полный SHA исходного коммита) и digest (SHA-256 текущего принятого scope). В decisions агент записывает основание согласования. После принятой дельты агент описывает точное изменение прав и обновляет digest, сохраняя base. Одного изменения Spec недостаточно. CLI проверяет совпадение суммы; авторство решения и подлинность Journal устанавливает человек или агент.

### R-2: Область разрешённых путей

Путь задаётся относительно корня проекта с разделителем / и сравнивается с учётом регистра. Звёздочка соответствует любой последовательности символов внутри одного компонента, включая точку. Конечное /** разрешает файлы на любой глубине внутри указанной директории. Точный путь разрешает только этот файл. Автоматически разрешены только Intent, Spec, Plan и Journal выбранного change. Эти правила действуют и для новых путей.

### R-3: Проверяемые изменения Git

Команда проверяет объединение путей разности деревьев base и HEAD, изменений индекса относительно HEAD, рабочего дерева относительно индекса и неигнорируемых untracked-файлов. Проверяются удалённые пути и обе стороны переноса. Изменения разных слоёв не погашают друг друга. При нарушении команда называет путь, слой и способ продолжения и возвращает ненулевой код. Код 0 означает, что все заявленные слои прочитаны и все обнаруженные пути разрешены.
